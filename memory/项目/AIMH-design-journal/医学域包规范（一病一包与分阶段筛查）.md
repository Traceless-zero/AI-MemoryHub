# 医学域包规范（一病一包与分阶段筛查）

> 本文件定义**医学内容怎么建包、FM 怎么填**。
> 引擎返回结果之后怎么处理（全量候选 + 无裁切 + `query_anchors` 参数集）见 `领域检索后处理规范（法律+医疗）.md`，两文件互补不重复。
> FM 字段契约的权威见 `SCHEMA.md`。

## 1. 方案 A：一病一包的包结构

医学内容按**一种疾病 = 一个 AIMH 事件包**拆分，每个病种独立成包、独立建索引，不做多病混装。

- 包内诊断内容**没有人物叙事**，故 `person` 恒为空容器 `[]`。
- **ICD 编码不是自然语言**，按「锚定物品」处理进 keyword，用法类比法律域的条号（条号/编码类 ID 都是强判别 token）。

沙箱验证：召回 11/11 全绿；接理解层 decomposer 后，用自然语言问诊口吻做模糊询问 7/7 全绿。

## 2. 四要素落点：发病位置填 location（更正旧笔记）

早前笔记断言医学域「地点维天然为空」——**这是错的**。疾病的发病位置即**解剖位点**，正好对应 `location` 四要素，是**强召回轴**而非空字段。

| 病种 | location 落点 |
|---|---|
| 冠心病 | 冠状动脉 |
| 肺炎 | 肺部 / 下呼吸道 |

这一更正把原本放弃的一维重新变成可用召回维度。

## 3. 五维 keyword 与变体写法

| 内容类型 | 落点 |
|---|---|
| 学名 | `topic` 规范名，canonical 形式进 keyword |
| 俗名 / 别称 | `topic` 变体 dict |
| 发病位置（解剖位点） | `location` 四要素 **+** keyword 地点维 |
| 症状 | `topic` 变体 dict（斜杠式）+ about |
| 治疗手段 | keyword 的「关键事件」与「锚定物品」两维 |

⚠️ 症状变体**必须斜杠式**：`气短/乏力` 是含 `/` 的**单一 token**，由 `_feat_alt_match` 的 `f.split('/')` 做 OR 匹配。拆成 `["气短","乏力"]` 两个逗号项会丢掉用户原话形态。

## 4. 症状重叠：医学域真正的消歧难点

医学包最难的不是检索而是**消歧**——症状跨病重叠，且存在不典型症状。

- **实测**：单症状实体「气短」→ 冠心病与心衰**打分完全相同（tie）**，最终只能按包名字母序排序（冠心病在前），等于消歧失败。
- **解法**：多实体 coverage 叠加。「气短 + 夜间憋醒 + 下肢水肿」三实体齐抽时，心衰 **281.6** 反超冠心病 **207.4**。
- **结论**：理解层 AI **必须抽足实体**；单症状实体在原理上无法消歧。这是医学问诊的固有难点，**不是引擎 bug**，因此 FM 不应为了消歧而删掉不典型症状（医学正确性优先）。

## 5. 分阶段渐进筛查流程

因为单症状无法区分病因，真实问诊**不能一次性锁定单病**，必须分阶段收敛。

**阶段一 · 问诊粗筛**
病人说的身体特征 → 理解层抽症状实体 → `query_anchors(package_agg=True)` 返回**候选病列表**（每病一条带证据分）——**此阶段不锁定单病**。

**阶段 N · 探查精筛**
化验 / 影像 / 体征报告 → 提取高判别力实体（BNP、NT-proBNP、肌钙蛋白、射血分数、冠脉 CTA、斑片状渗出、白细胞↑…）→ 叠加进候选池 + `scope` 锁定缩圈 → 逐步收敛到单一诊断。

⚠️ 引擎是**零 ML 无状态**的，**跨阶段候选池由编排层（理解层 / AI 应用）维护**，不是引擎职责。`query_anchors` 已有的 `package_agg` / `scope` / `context` 三参数直接支撑该架构，无需改引擎。

## 6. FM 补锚点与专业域 LLM 角色边界

- 每个病种包**必须补一个「客观检查 / 诊断标准」锚点**，承载 BNP、肌钙蛋白这类高判别力实体——否则阶段 N 精筛时这些实体**无处命中**。
- **专业域 LLM 角色被严格限定为只做关键词提取**：把病人自然语言描述抽成实体词，交给 `query_anchors` 的 `decomposer` / `keywords` 接口，**零诊断**。
- 引擎返回全量加性分候选池 → 前端网页把 top 候选列表**展示给人**做鉴别判断。

单症状无法消歧这个死穴，正是由「把全量候选并列展示给人看」自然化解——人看到心衰与冠心病并列，立刻知道要补查。这正是 CEMA 分工的落地：**AI = 理解层（抽取）、引擎 = 确定性检索、人 = 最终判断。**
