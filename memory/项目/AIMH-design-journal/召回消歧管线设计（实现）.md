# 召回消歧管线设计（实现）

> 配套文档：`召回消歧的数学与语言哲学思路.md`（为什么这样设计）。本文档讲**落成后的管线长什么样**。原型在 `sandbox/query_routing/resolve_query.py`（确定性、零向量，含 EXACT/DICT/LLM/clarify 四阶段）；生产引擎已落地等价能力于 `hma/hma_core.py` 的 `Memory.resolve_query`（包裹既有确定性 `query()` 召回 + 歧义门 + 负特征差集塌缩 + 特征判别澄清），集成测试见 `sandbox/query_routing/test_resolve_integrated.py`（16/16 绿）。

## 0. 一句话

查询走一条**确定性四阶段管线** `EXACT → DICT → LLM → clarify`：先用原词精确命中，未中则同义词词典扩展，再不中则 LLM 把自然语言「翻译」成四要素字段值再查；任一步命中即进**歧义门**判 return / clarify。**向量（数字比对）全程不入场**——它是对确定性大脑的概率黑盒，而 LLM 只是确定性大脑外的「翻译官」，每句话可审计、可纠错。

## 1. 管线总览

```
query
  │
  ├─ EXACT  精确/子串匹配（锚点级 + 字段加权）
  ├─ DICT   同义词词典扩展 → 再查 index.db
  ├─ LLM    映射层把 NL 翻译成字段值 → 再查 index.db
  │
  └─ 任一步有命中 ─→ 覆盖门（区分词唯一锁定？）─ 是 → return（stage=coverage_gate）
                      └─ 否 → 歧义门 _decide ─┬─ 单实体 ─→ return（直接返回）
                                               └─ ≥2 实体 ─→ ① 负特征差集塌缩
                                                               ├─ 塌到单候选 → return
                                                               └─ 仍≥2 → 特征判别澄清（亮独有弧段）
  全阶段零命中 ─→ 澄清兜底（返回候选标题供指认）
```

- 三阶段串行、命中即停（早停省算力）。
- LLM 只在 DICT 不中时才调用，且原型用 `_mock_llm`（同义词词典 + 值域 fuzzy）零成本模拟；生产换真实 LLM 调用，其余管线不变。
- 覆盖门（§1.1）在歧义门之前先判『能否不问就定』——强区分词直接把用户送到底，省一次澄清。

### 1.1 覆盖门（软·强信号快捷通道，2026-08-20 落地）

`resolve_query` 在实体去重 / 歧义门 / 澄清**之前**先判『区分词能否唯一锁定候选』：

- **区分词** = 查询 token 中仅命中 top-K 候选恰好 1 个者（如 `纯净蓝` / `孤品` / `2005`）。
- 若全部区分词指向**同一候选** → 直接 `return`（`stage=coverage_gate`，附 `discriminators` 区分词清单），跳过澄清；无区分词 / 区分词分裂 → 回落既有歧义门。
- **软门非硬 AND 过滤**——不要求所有词必中（防 over-abstain / paraphrase 删空），误杀 0。
- 区分词检测范围 = 召回 top-K 池（`top_k×2`）；匹配用包级可检索 blob 的**连续子串**（不做 CJK 二元扩展，避免 `纯蓝` 误中 `纯净蓝` 被当区分词）。
- 这是「澄清红利」的自动化：top-K 已含答案时强区分词直接把用户送到底（`纯净蓝` → 苍穹之泪 / `孤品` → 示例信物），只有真正需要挑时才进澄清门（`蓝+钻石` 两枚并列 → 澄清）。
- 验证链：沙箱原型 `sandbox_test_coverage_gate.py`（唯一召回 100% / 误杀 0 / paraphrase 安全）→ 生产实装 `hma/hma_core.py` `_coverage_gate` → 回归锁 `scripts/tests/regress_coverage_gate.py` 10/10。

## 2. 字段加权与中枢偏置（hub-bias）

锚点级粒度 + 字段加权，解决「概览包因 summary 命中多反而压过具体锚点」的中枢偏置。

| 字段 | 权重 | 说明 |
|---|---|---|
| `kw`（锚点关键词） | 3.0 | 精准消歧信号，最高 |
| 四要素（person/topic/location） | 2.0 | 一等字段，次高 |
| `chapter`（锚点章标题） | 1.5 | 选章定位键 |
| `title` | 1.0 | 表面标题 |
| `about`（锚点梗概） | 0.5 | 消歧用，最低正文权重 |
| `summary` | 0.3 | 概览包易 hub 偏置，压到最低 |

`_build_units()` 把一条 package 拆成带权重的检索单元（标题/summary/四要素/每个锚点的 keywords+chapter+about），命中得分 = 命中单元权重之和。权重越高越能压过概览噪声——实测把「宝石」类查询从「起源史诗」错排拉回「第四阶段·示例信物」正确锚点。

## 3. 歧义门（`_decide`）

澄清的开关是**歧义（多个候选），不是零命中**——这正是「向量遇模糊硬猜最近邻」的确定性镜像：模糊查询遇多候选 → 反问，而非替用户拍板。

- **实体去重键 `ekey`**：从标题抽规范名（截 `（别名` / ` · 分章` 后缀），同角色的基础包/拓展/背景故事三行归并为一个候选，消除多副本/多锚点假歧义。
- 判据：`去重后实体数 < MIN_CANDIDATES(默认2)` → return；`≥2` → clarify。
- 旋钮：`AMBIGUITY_FLOOR`（候选最低分，过滤弱命中噪声）、`MIN_CANDIDATES`（歧义阈值）。

> ⚠️ 实测坑：去重键若用 `title_of[package_id]`（按包取首行标题）会让同包多行变成多个实体 → 假歧义触发澄清。正确做法是每条命中携带自身 `ekey`，按 `ekey` 去重。

## 4. 特征判别澄清（`_build_clarify`）

歧义时不丢候选标题（用户常记不住名字），而是亮出每个候选的**独有弧段**（判别特征），让用户用特征指认。

- **独有弧段** `d(e) = F(e) \ ⋃_{e'≠e} F(e') \ A`：自身特征减其他候选特征并集（Venn 不相交部分），再减 `A`=锚点共现噪声集（`_anchor_only_tokens`：仅出现在锚点 keywords、不在任何结构化字段的 token——如故事里顺带提到的配角名示例人物/弗瑞。2026-08-19 方案 C 加入，避免澄清卡亮出配角）。
- **特征只取结构化维度**：person 规范名/别名、topic、location、锚点 keywords、tags；**排除**自由文本 title/summary/about/chapter（粒度太粗，会让每个候选都「看起来独特」）。锚点 keywords 仅当 token 同时出现在结构化字段时才算特征（anchor-only 的共现噪声被剔除）。
- **IDF 排序**（特异性梯度）：独有弧段按 `全局共享实体数升序`（拥有者越少=IDF 越高=越靠近圆心）→ `中心度层级降序`（person > 锚点 kw > topic > tags）→ CJK 优先。最靠近圆心的规范名排最前。
- 生产环境：LLM 把独有弧段措成自然语言反问，如「你指的是 (A) 代号示例别名、自由佣兵的示例角色，还是 (B) 代号黑寡妇的示例人物？」

## 5. 负特征对偶（`_neg_features_from_query` / `_apply_negation`）

加入近中心性质 = **正算子（集合交）**；「不是 X」= **负算子（集合差 / 排除）**。两者都塌缩重叠区，构成「向圆心聚焦」的完备操作集。

- 抽否定子句：定位 `不是/排除/除了/非/别是/不要` 等标记后的子句，从库内特征里挑双向子串相关的 token 作为否定特征（生产应换 LLM 精准解析）。
- 差集塌缩：删除任何拥有否定特征的候选实体；塌缩到单候选即聚焦成功、直接返回，不再进澄清。
- 演示：`那个冷战时期的特工，不是黑寡妇那位` → 排除示例人物·罗曼诺夫 → 重叠区塌缩成示例角色单圆。

| 数学思路（为什么） | 本管线（怎么做） |
|---|---|
| 特征词=边缘性质→易相交 | `_decide` 判歧义、亮独有弧段 |

## 7. 交互澄清的呈现契约（Agent 侧）

歧义门吐出的是 `payload`（见 §4），它只是「结构化事实」，真正让用户秒懂的是 Agent 把它**翻译成自然语言反问**的呈现层。契约如下：

- **输入**：`payload["candidates"] = [{ekey, title, rid, summary, unique:[...]}]`，每个候选已按特异性梯度排好独有弧段，并带 `summary`（该候选代表包的 front-matter summary，供 Agent 润色时组织简介）。
- **MCP 坍缩层（`hma/server.py::_h_resolve`）**：`resolve_query` 的原始 JSON 结构是**引擎↔AI 契约，不直见用户**。`_h_resolve` 先把 `decision:"clarify"` 坍缩成紧凑文本（每候选一行：`title (rid)` + `简介: summary` + `判别特征: [unique[:6]]`）作为 MCP 工具结果回给调用方 AI。
- **翻译角色（LLM）**：把工具结果文本里的 `简介` + `unique[:2]`（最靠近圆心的 1–2 个判别特征）措成「你指的是 (A) … 还是 (B) …？」句式，而非罗列标题。
  - 例：`unique=["示例别名","自由佣兵"]` + `unique=["黑寡妇","示例人物·罗曼诺夫"]`
    → 「你指的是 (A) 代号示例别名、自由佣兵的示例角色，还是 (B) 代号黑寡妇的示例人物·罗曼诺夫？」
- **降低认知成本**：优先用**负向**措辞（若用户此前给过否定子句，直接复述「已排除 X」），让用户用最省力方向确认。
- **回填闭环**：用户指认某个候选后，Agent 用其 `rid` 调 `read(rid)` 取正文，或把指认结果塞回后续查询（把「那个特工」替换为规范名），消除本轮及后续轮次的歧义。
- **不替用户拍板**：澄清是反问、不是猜测；Agent 绝不自行选一个候选当答案（那是向量「硬猜最近邻」的行为，确定性镜像的反面）。
- **落空兜底**：若 `payload` 为空（双不中），转零命中兜底——返回候选标题或「未找到相关记忆」并请用户换表述，不编造。

## 8. 多跳歧义（沿 linked 扩簇）

单跳歧义门只在「查询直接命中的实体」之间判歧义；`recall_multihop` 把视野沿 `linked` 放大后，必须重跑歧义门。

- **扩簇**：对每个单跳候选 `e`，沿 `linked` 边取其可达簇 `C(e) = { x : x 可达自 e }`（含 e）。
- **簇粒度重算**：特征集 `F(C(e)) = ⋃_{x∈C(e)} F(x)`；候选簇集 `D* = { C(e) : e ∈ S }`；独有弧段 `d(C(e)) = F(C(e)) \ ⋃_{C≠C(e)} F(C)`。
- **机制复用**：`resolve_query` 的实体去重（ekey）、歧义门（`|D*| ≥ 2`）、特征判别澄清（`_build_clarify` 直接吃簇特征集）、负特征差集塌缩，全部原样作用在簇集 `D*` 上——只需把「实体特征索引」换成「簇特征索引」。
- **风险**：扩簇并入更多边缘特征 → 重叠区变大 → 单跳清晰的实体扩簇后可能落入更广重叠，反而更歧义。故多跳召回增强**绝不能跳过歧义门**。
- **现状（V1.0 已落地）**：`recall_multihop`（沿 linked BFS 扩簇）已在 V1.0 接入生产 `resolve_query(multihop=True)`，把扩簇结果喂给既有实体歧义门（机制复用，无需重写消歧逻辑）；回归见 `sandbox/query_routing/`（已于 2026-08-15 归档至 `to_delete/`）`test_multihop.py`。

## 9. 写入侧反推：落库完整性检查（源头消灭歧义）

对应数学文档 §9。读取侧歧义门再聪明，也要求用户**每次查询**付一次认知成本；写入侧反推把这笔成本前移到**一次写入**，让易混淆实体在落库时就被迫拥有至少一个独有弧段。

### 9.1 管线位置：插在 `write()` 落库后（不阻断）

- 钩子挂在 `Memory.write`（落库函数，原子写 .md + upsert 索引）的 `_upsert` 之后：先跑一遍 `_entity_feature_index`（已有）+ `global_count`（已有），对**刚落库的那一个实体**算独有弧段与拥挤度。
- 默认**关闭**且不阻断写入：`write(integrity_check=True)` 才返回 `{path, warnings}`，否则仍返回 `path`（旧契约不变）。检测成本近乎为零：两个结构已存在，无新依赖、不调 LLM。

### 9.2 检测判据（与代码 `_missing_unique_arcs` 一致）

- **硬缺失 · 独有弧段为空**：实体有结构化特征，但每个特征都被 ≥1 其它实体共享（global_count 全部 ≥2）。任何命中它的查询必落多圆交集、必触发歧义门。
- **惰性实体跳过**：无任何结构化特征（F(e)=∅，如纯随笔）不判——它只是不可被特征召回，非歧义风险，避免误报洪流。
- **软缺失（预警）· 有独有弧但处于拥挤邻域**：独有弧（global_count==1）存在，但与其共享 ≥1 特征的「邻居实体数」`share_count ≥ k`（`k` 默认 3）。提示补更具体关键词，但不阻断落库。
- 注：数学文档 §9 已校正——严格独有弧 global_count==1 故 `G(e)` 恒为 1，软缺失改用「共有邻居数」`share_count` 衡量拥挤度，比原 `G(e)` 提法更可执行。

### 9.3 提示与闭环

- **提示模板（Agent 侧）**：warning 载荷自带 `suggest` 字段——「「{title}」{reason}；请给它一个别处用不到的独有关键词（某条独有属性 / 代号 / 场景），写入 person/location/topic 规范名变体或锚点 keywords，使其获得至少一条 global_count==1 的独有弧段。」
- **关键词落点**：优先补进 `person/location/topic` 四要素 dict 的规范名变体（读取侧加权最高）；其次锚点 `keywords`；再次 IDF 高的 `tags` 值。
- **闭环**：用户补完重算 `d(e)`，须变为非空（含 global_count==1 的弧段）；否则继续提示。写入侧只是把「查询时刻的歧义门」提前成「落库时刻的完整性检查」。

## 11. 查询作用域策略（scope-first，被质疑才升全局）

性能哲学（2026-08-17 拍板 **C**）：AIMH 查询主流是包 / 日log 内，**`scope` 即可把 O(总锚点) 塌成 O(该包锚点)**，零 schema 改动、免 `rebuild` / 重载 MCP，最贴合分包设计。全局 `search_blob` 索引只是给「跨包存在性判定」上的保险，**不是默认路径**。

- **默认 = 聚焦（scope）**：能带 `scope` 就带（相关包 / 日log 包 / 命名空间）。MCP `memory_query_anchors` 优先填 `scope`（或 CLI `--package <pkg_id>`）；不填 scope 才退全局。
- **升级触发 = 用户质疑「明明就有」**：聚焦查询返回 `(ABSTAIN: out_of_scope)` / `(no match)`，而用户反驳「我明明记过这个 / 就在 X 包里」时，**不要直接认输**——重新发一次**全局 `search_blob` 复查**（省略 scope 或 `--all`，仍 `allow_abstain=true`）。blob 全局路径已验证零召回回归，会跨包找实体；找到则回带包路径给用户，找不到才维持拒答。
- **为何不默认全局**：聚焦覆盖 90%+ 用法且零成本；全局 blob 仅在「被质疑」这一窄场景启动，避免每次查询都扫全库。scope 是主路径，blob 是全局升级的安全网，两者不冲突。
- **铁律**：聚焦查询拒答 ≠ 最终结论；**用户一质疑，必升全局复查再下结论**（升级也拒答才算真没有）。
- 落地状态：生产引擎**无需改动**——scope 分支与 `search_blob` 全局路径早已就位，本策略是纯策略 / 技能层决策（见 `aimh-recall` SKILL.md「作用域优先策略」段）。

## 12. 命中数护栏（TOP1 接地，超出强制交互澄清）

防上下文爆量 + 防「列清单式回复」（2026-08-17 拍板，当晚细化）：召回结果**绝不无脑全量灌进回答，也不列 top3 清单**——只基于 **TOP1（最佳单条命中）** 接地回复。

- **回复基于 TOP1**：命中后只取 score 最高的那一条，把它精确接地成回答；**不列举 top3 / 不堆多条候选**让用户在列表里挑。TOP1 即答案。
- **引擎 `top_k` 上限 ≤ 3**（内部安全网，防 top100 爆上下文）：仅用于判「是否还有更多候选」，不用于向用户展示列表。
- **命中 > 3（或候选明显发散）**：仍**先给 TOP1 的回答**，但**立即启动交互澄清**确认是不是这条：
  > 据记忆最相关的一条：<TOP1 接地回答>。若不是你要的（相关记忆还有多条），告诉我，我按 `scope` 收窄或换关键词再查。
  **绝不**把第 4 条往后的正文一股脑返回，也**不**列 top3 让用户选。
- **怎么判断「>3」**：单 `top_k=3` 只看得到 3 条；若怀疑候选更多（同名实体多包命中 / 用户问法宽泛），先以 `top_k=4` 探一下是否有第 4 条，有则按上条强制澄清；或据 abstain reason / 包分布直接判定发散。
- **铁律**：回复永远只落地 TOP1；超量即「TOP1 回答 + 澄清」，AI 不得自行决定列清单或全量返回。澄清后用户指明某条 / 收窄 scope，再针对性取那条正文接地。
- 性质：纯 Agent 行为规则，不涉及引擎代码（呼应 §11 的极简取向）。与 §3 歧义门的区别——歧义门管「身份歧义（多个候选是谁）」，本护栏管「数量爆量（命中太多）」，二者独立、可同时触发。


## 13. 长尾细节锁章召回（obscure_recall · 人机共审）

针对一类特定失败模式：具名实体（锚点级召回）能精确命中，但**不起眼物件**（出现多次、无锚点位、与地点词常不在同一窗口）的细节追问会卡死在「机械层选不出描述段」。生产工具：MCP `memory_obscure_recall`（转发 `Memory.obscure_recall()`；参数 `q` / `obj_token`（必填，特征实体词）/ `package_id` / `scope_chapter` / `scope_mode`(explicit|reading|global) / `top_k` / `window`；返回 route / route_one_read / cards / auto_abstain 结构化 dict）。

**原理上限（铁律）**：机械层独立搞定细节问答在零-ML 确定性系统里本质不可达——那要求写入侧预知未来所有查询角度（拉普拉斯妖），违反 CEMA「写入确定性、不猜未来」。选段是语义判断，归理解层/人；机械层只管「不漏 + 不爆」。正确姿态：precision 责任交给人机共审。

**两条路线（正交，先判定再走）**：

- **路线一（范围候选 · AI 自读）**：锁章切片后把片段集直接交 AI 自读出答案（precision 由 AI 在窄语境承担）。适用：问法带明确章级语境且片段内可直接读出。
- **路线二（C+A 段卡片 · 人机共审）**：每候选段以 C(Chapter)+A(about)+段原文 三段式卡片摊开，系统绝不单方出答案，终审权在人。适用：噪片段多 / 用户要自己筛 / AI 自读也不可靠。
- **降级铁律（单向强制）**：路线一自读后判断候选集无真段 → 必须自动拒答转路线二，不得硬答、不得停留。

**公共前置（两路线共用）**：context-scope 锁章 → 章内局部倒排（特征实体每个出现处切 ±200 窗口）→ 重叠合并瘦身（交集/较小区间 >0.5 即并集；不同语境段全留）。三级范围信号递减：用户显式指章=强信号直接锁章；会话阅读位置=弱信号缩圈但**不排他**（章内没找到必须回退全包宽召回）；无信号=全包宽召回。

**C+A 卡片字段约定**：C=锚点 Chapter 原样照搬；A=实质锚点 about（无匹配锚点如实标注，不编造）；段=±WINDOW 原文不摘要不改写。噪片段靠 C+A 自显，人扫一眼即判。

**护栏**：共审纯读取侧不落盘（不反向写锚点）；私有包按 C 类不碰；严禁在呈现层外自行归纳确定性结论冒充回答。回归：`regress_obscure_recall.py`（R1-R4）；沙箱：`sandbox_obscure_context_scope.py` / `sandbox_obscure_object.py` / `sandbox_obscure_slim.py`。


## 14. 召回操作协议（驱动侧执行细则 · 原 aimh-recall 技能收编）

### 14.1 检索例程（CLI 兜底）

`python -m hma.engine query_anchors <root> "<实体>" --all`（L2 锚点级，推荐）/ `python -m hma.engine query <root> "<关键词/标签>" --all`（L1 包级定位）。`<实体>` 直接用具名原文；--all 全局扫描。等价 Python API：`Memory(root).query_anchors(q, top_k, use_field_weights=True, allow_abstain=True, keywords=[...])`。

### 14.2 理解层关键词提取（真·功能接口，优先于机械拆词）

query_anchors/resolve_query 内置 CJK 二元拆词只是无 AI 接线兜底。正确路径：理解层先把问句解析成复合实体词，经 keywords 传入（「量子计算的最新进展」→ ["量子计算","最新进展"]）。传入即启用 corpus_missing_entity 硬拒答闸：判别实体语料查不到 → 拒答。域内题必在语料不误拒；域外题正确拒答。机械拆词永不作主力。

### 14.3 REFINE（Q 桶真空/多跳兜底，理解层职责）

P 桶（查询自洽）引擎 100%；Q 桶（真空/多跳，实体需跨上下文消歧或 linked-BFS+REFINE 路由）零-ML resolver 不预期 100%，失败属逻辑必然，交 REFINE——一步常识桥接（"最值钱"→"宝石"→命中示例信物）。生产 REFINE 由 LLM 完成（query→关联实体词），注入点为 query/resolve_query 的 `decomposer=` 参数；无 LLM 时该环节诚实缺位——Q 桶失败由拒答闸兜底（2026-09-06 零-ML 词典实现随孤儿清理移除，转述桥接定界归驱动层）。多跳路由用 memory_resolve(multihop=true)：先 linked 双向 BFS 扩簇再跑歧义门，比裸 memory_query(multihop=true) 多一层歧义判定。

### 14.4 路径协议（首次/失效时跑，禁止推理猜路径）

①读 `~/.hma_home`（一行=仓库根）；②缺失/失效 → `python <repo>/scripts/core/where.py --json` 登记；③都不可得 → 问用户。CLI 一律 cd 仓库根执行。

### 14.5 拒答层细节（faithfulness gate）

allow_abstain=true 必带。三道确定性闸门：empty_pool（BM25 无命中）/ low_coverage（top 锚点 IDF 加权覆盖度 < κ=0.34）/ out_of_scope（四要素解析出实体但召回包零命中）。ABSTAIN → 直接说「记忆里没有/不确定」，绝不编造；reason 只供判断不念给用户；confidence=low 先 refine 再答。命中接地：回答基于取回内容并标注来源（据 HMA · pkg_id）；多命中按分取 top，只接最相关 1-3 段；未命中静默放过。

### 14.6 时间描述唤起（读侧）

用户用时间描述回忆（「前天干了什么」）：①时间语解析成 ISO 日期/区间（不确定就问）；②daylog 读取经 `hma.daylog` 模块 `read_day(<date>)` / `days_in_range(...)` 取叙事（写入走 daylog_append.py）；③细节沿条目 linked id 用 memory_read_section / memory_query_anchors 取主题包正文。时间只是过滤键，不做新鲜度加权。
