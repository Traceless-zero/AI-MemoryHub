# 存储架构总览（各分支存储契约）

> AIMH 记忆库按**命名空间**组织。本文档是各命名空间 / 分支的**存储契约总览**：
> 每个分支「落在哪、长什么样、有哪些特殊语义、怎么检索」。
> 通用事件包模型在 §0；daylog / project / OC / 对话 / user / 其他 在 §1–§6 逐支细分。
> 字段级细节去 `SCHEMA.md`（§2 front-matter V2）；AI 收录时的**路由与拆包决策**去 `SCHEMA.md`（§4 命名空间与拆包契约）（本文档只讲"存成什么样"，不讲"往哪落"）。

## 多根布局（多代理 / 公共目录）

多代理场景的隔离与共享都在**根级**用目录解决，存储层不做任何强制机制：

- **代理私有根**：`agent_A/`、`agent_B/` 各为完整记忆根（各自 memory/ + index.db），经 MCP `--root` / where.py 指针分别挂载。隔离是物理的（不同文件），写并发随隔离消失（单根单写者），备份/迁移/删除都是整目录操作。
- **公共根**：再建一个 `公共/` 记忆根，与 A/B 平级平权——用户画像、公共知识放这里，各代理按需挂载读取。
- **读写边界归协作规则**：谁可读写哪个根，是用户约定与代理协作纪律的事，不是存储层的机制。违规可由 git 历史 + rebuild + 审计链回溯纠正——与全仓治理方式一致。理由：多代理服务的是**同一用户**（可信、共居），不是 SaaS 式的不可信外部租户；把强制机制埋进存储层属于为不存在的威胁加结构。

## 0. 通用存储架构（事件包模型）

所有分支共享同一套底层，差异只在**落点目录 + 个别 front-matter 约定 + 正文结构**：

- **事件包 = 一个 `.md`**（YAML front-matter + `##` 标题树）是**唯一权威源**；`index.db` 是派生缓存，删了可由 front-matter 全量重建。
- **CEMA**：前后台严格 1:1；无向量 / 无嵌入；检索只发生在索引层，命中唯一 ID 后才取正文。
- **front-matter 即索引字段**：`title / summary / tags / linked / anchors`（必填/常用）+ 四要素 `person / event_date / location / topic` + `pkage_created / pkage_updated`（引擎托管）。字段语义、类型、持久化见 `SCHEMA.md`（§2.4 四要素）。
- **anchors = C+A 对象锚点**（`{Chapter, about, keywords}`）；正文 `##` 即章；pageIndex 模型（翻目录 + about 选章，正文不进选分）。见 `SCHEMA.md` §2.7。
- **检索漏斗**：L1 `query`（包级）→ L2 `query_anchors`（章节级）→ L3 `read_section`（正文段）；锚点级已升级为 **F + C+A + READ 三段式**（features 两跳精准门 + Chapter/about 消歧 + READ 取正文 + 循环查询）。
- **写入方**：AI 理解层（`aimh-ingest` / `oc-dossier` / `aimh-project` / `aimh-archive` 等技能判定与拆分）+ 确定性引擎落库（`Memory.write` / `scripts/`）；零向量、零嵌入、理解归 AI 写归脚本。
- **隔离拓扑**：命名空间**目录硬隔离**（用户 / 项目 / 原创角色 / 日志 / 其他 / 对话 + `cache`）；详见 `SCHEMA.md` §4。

## 1. daylog（日志 / 事件流权威源）

**落点**：`memory/日志/daylog-YYYY-MM-DD.md` —— 一天一份，文件名内嵌日期，日期即主键。由 `scripts/core/daylog_append.py` 写入（脚本负责建文件 / front-matter / 序号 / 时间戳，AI 只给正文与标签）。

**它是什么**：daylog 是**唯一事件流权威源**——当天发生的事（决策 / 改动 / 踩坑 / 讨论经过）详实内容只写在这里，写完冻结、只增不改。与主题包是双轨分工：**事件**进 daylog（权威于过程），**作品**（会被改写的活文档：随笔 / 档案 / 规范 / 约定）进主题包（权威于结论），靠 beat 的 `linked` 互指。

**AI 写入零路由**：对日志永远只做一件事——向当天 daylog 追加一条 beat，不做「归到哪个项目 / 模块」的判断。按主题浏览由 `scripts/core/derive_topic_views.py` 机械派生（各包 `开发日志.md` + `日志/主题索引.md`），派生物带「本文件由脚本派生」标记、禁止手改、可随时重建。设计定稿见 `daylog设计.md`。

**beat 块格式**（`## 流水` 节下）：
```markdown
### 01 · 一句标题 · 14:22
- touched: [hma/server.py, 项目/AIMH/SCHEMA]
正文（事实/决策/改动，详写）
<!--beat linked:项目/AIMH/开发日志 tags:读取链路,MCP-->
```
- 序号 / 时间戳由脚本落；`touched` = 本次实际碰的文件（AI 显式传入，脚本校验存在性）；`linked` / `tags` 写入时打标，可为空。

**front-matter 特例**：`event_date` 填当天日期（区别于概念文档的 `"—"`）。

**起包**：同一标签在 ≥3 个不同日期出现 → 主题索引顶部列起包建议；建议由脚本给、决定由用户做；起包后旧条目不回搬（召回与文件位置无关），新 beat 的 `linked` 改指新包。

**纪律**：详实内容只写 daylog 一处；`开发日志.md` 是派生视图、永不手写；一次性内容永久留 daylog 不搬家。

## 2. project（项目工程）

**落点**：`memory/项目/<项目名>/`。

**README 式功能拆包（读者视角，非子系统视角）**：仿照一个普通项目的 README 做功能拆包，而非按技术子系统（引擎/技能/MCP/检索）切。一个 `.md` 装一类职责：

- **需求清单**（`<项目名>/需求清单.md`）：项目要做什么，**显式标 `已完成` / `未完成`** 状态（类似 roadmap / backlog）。这是项目的"活待办"。
- **项目结构**（`<项目名>/项目结构.md`）：只描述目录与文件布局。**严禁把铁律 / 约定 / 架构决策等"死东西"塞进此文件**——结构就是结构。
- **开发日志**（`<项目名>/开发日志.md`）：按时间顺序的工程记录聚合视图，由 `derive_topic_views.py` 从 daylog 的 beat 机械派生（每条一行摘要 + 回跳锚点），**永不手写**。
- **约定 / 铁律**（`<项目名>/约定.md`）：把"死东西"（编码铁律、协作约定、不可违反的规则）单独成文件，与结构、日志解耦。
- 其余按需：`架构.md` / `接口.md` / `测试.md` 等，每个 md 单一职责。

> 与"按子系统切"的区别：子系统切是**实现视角**，README 式拆包是**读者视角**——新人打开项目先想"要做什么（需求）、长啥样（结构）、怎么变的（日志）、啥规矩（约定）"，而非"引擎代码在哪"。

## 3. OC（原创角色）

**落点**：`memory/原创角色/<char>/`（`<char>` 如 `demo-char` / `luzhao`，按角色定拼音/英文名）。

**三层铁律切片（两路落库都守）**：
1. **基础包（必有，仅 1 个）** = 姓名 + 形象 + 语气 / 调性。这是「AI 能基本扮演」的最小可运行单元（`{id}-base`）。无论 OC 多浅多深，这一层永远只有 1 个包。
2. **origin 包（背景故事包，默认必有）** = 人物背景故事，**无论长短独立成包**（`{id}-origin`）。哪怕只有一行字 / 一句短语也单独拆出（极简 OC 的 origin 包可仅一句「出身于 XX 渔村」）；**只有确实没有任何背景故事的 OC 才省略 origin 包**——不再有「短就并进基础包」的模糊阈值判定。内部用锚点索引实现细粒度召回，**不切碎文件**。
3. **拓展包（有则分）** = 感情 / 与其他角色关系 / 战衣 / 武器 / 能力 / 信条……只在存在时才分立（`{id}-ext`）。极简 OC 可以一个拓展包都没有。

**不可违反的规则**：
- **长叙事原样收录，禁止综述化 / 压缩**：起源史诗、人生经历等超长文本，按原文长度完整写入 origin 包正文；AI 不得重写、精简、或自造小标题。需要细粒度召回时，用索引层锚点，而非切碎文件。
- **一个角色一个基础包**：不得把姓名 / 形象 / 语气拆成多个包（已踩过的反例）。
- **不动用户 OC 源文件**：抽取走读副本，草稿残留、笔误等由用户手动清理，AI 不擅自修改源文件。

**唤醒（只读不写）**：从 `base_id` 启动（载入「姓名 + 形象 + 语气」即为扮演最小单元）；仅当用户问到具体内容时惰性召回——问「过去 / 起源 / 经历」→ origin 包 `query_anchors` 取摘要 / `read_section` 读整段；问「能力 / 关系 / 信条 / 拓展设定」→ `read_section(ext_id, "对应小节标题")`。详见 `oc-dossier` 技能。

## 4. 对话记录（talking）

**落点**：`memory/对话/<主题或会议名>/`（新增顶层命名空间，与 用户/项目/原创角色/日志/其他 并列；可按主题/项目在下方嵌套，如 `memory/对话/项目A进度会/`）。

**存储结构（推荐样式，沙箱 `test_anchor_slim` 已验证）**：
- `summary` = 谈话背景（这场在聊什么，短、不混入结论）。
- `## 对话原文` = 逐字 transcript，每轮 `时间戳 | 对话人：对话内容`。
- `## 关键内容` = 这场对话**最后拍板 / 确定的事**，每条 `时间戳 | 决定内容`（清水决策层，默认返回粒度）。
- `anchors` = 两段 C+A 锚点（对话包标准样式）：
  ```
  anchors:
    - {Chapter: "对话原文", about: "本场逐字讨论的要点（议题/分歧/未决项）", keywords: ["对话原文", "逐字", "讨论"]}
    - {Chapter: "关键内容", about: "本场最后拍板/确定的事项要点", keywords: ["关键内容", "拍板", "决定"]}
  ```
  两段各以 Chapter 标题定位对应 `##` 小节；查「讨论过程」落对话原文、查「拍板了什么」落关键内容，READ 精准不扫全篇。新写对话包用 C+A 两段。
- `person` = 对话参与方（人+AI：如 `[Alex, assistant]`；会议填与会者）。

**tags 由关键内容派生（单一真相源约定）**：对话记录的 `tags` 必须从 `## 关键内容` 每条决定中抽取的**决策主语 / 规范实体**得来；`关键内容` 是唯一手写真相源，`tags` 永远由其派生、不手工另写——根除双写漂移。细则（为什么 / 纪律 / 反例正例 / 验证）见 `SCHEMA.md` §2.9。

**矛盾 / 反向更新处理（引擎立场）**：引擎只负责把相左事实**都忠实保留、都检索得出来**；是否矛盾 / 该用哪条，由 AI 理解层判定，**绝不在写入时静默覆盖**旧决定（每场会议独立成包）。反事实询问（用户陈述与记忆冲突）要区分"记错"vs"过时更新"；缺失信息诚实说"未记录"，**不编造日期**。细则见 `SCHEMA.md` §2.9。

## 5. user（用户数据）

**落点**：`memory/用户/<模块>/`。

**铁律（q-2）**：主语必须是**用户本人**，不进话题类目（话题类内容归 项目 / 其他）。

**默认五个凝聚模块**：

| 模块 | 装什么 | 不装什么 |
|---|---|---|
| `偏好` | 稳定偏好 / 习惯 / 工具与风格选择 | 一次性临时的选择 |
| `方法论` | 可复用的工作/思考方法、"以后这么做" | 具体某次的项目决策（归项目） |
| `身份锚点` | 自我描述 / 角色定位 / 长期身份事实 | 易变的短期状态 |
| `踩坑` | 具体教训、易错点（"别踩"） | 正向方法（归方法论） |
| `事实` | 与项目无关的稳定个人事实（家住 X、用 X 设备） | 项目相关事实（归项目） |

> 模块是**默认路由指南**，不是强制分类法。AI 收录时先判内容命中哪个模块，再落点；小内容可先作为同包内的不同事件 id，不必硬拆成独立包（拆包触发条件见 `SCHEMA.md` §4.3）。

## 6. 其他（文章 / 资料 / cache）

- **其他** = 文章 / 杂项 / 资料文本。走 `aimh-ingest` 文章 / 资料分支：`<主题>-orig` 原文包 + `<主题>-review` 综述包，二者互链（原文包存全量、综述包存理解层摘要）。
- **cache** = `aimh-archive` 压缩归档溢出落点 `memory/cache/archive/<eid>.md`，临时缓存包（散碎、暂无归属主题），命名空间已注册进 `tree.py`；权威正文永远在主题包，cache 只作溢出兜底。
