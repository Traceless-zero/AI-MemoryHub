# 工具与技能总览（脚本 + 技能）

> 本文合并了原「py 脚本介绍和使用流程」「SKILL 介绍和使用流程」两份文档。
> 脚本层是「确定性操作」的承载者——落库、建索引、装卸、重建索引全在这里，**永远不吃 token**；
> 技能层是「可插拔客户端」：Agent（当前对话 AI）即免费理解层，skill 定义它如何把输入路由到引擎 CLI / 脚本。

---

## 一、两个命令行入口

AIMH 提供两套互补的命令行入口（均直读/直写 `memory/`，`.md` 权威源、`index.db` 可重建）：

- **`hma.cli`**（`python -m hma.cli`）：写/链/列/显/收录类——`write` / `link` / `rebuild`(单包) / `show` / `list` / `ingest` / `query`。
- **`hma.engine`**（`python -m hma.engine`）：引擎检索/维护类——`query` / `query_anchors`(L2 章级) / `derive`(重派生锚点) / `rebuild-all`(全仓) / `install`/`uninstall`(装卸包索引) / `modes`。`tree` 已停用；`daylog` 已从 CLI 卸除。

```bash
# —— hma.cli：写/链/列/显/收录 ——
python -m hma.cli --root <包目录> write --id X --title T --summary S \
      --tags a,b --linked A,B --person "P1,P2" --anchors '[...]' --body "..."
python -m hma.cli --root <包目录> link A B          # 双向关联
python -m hma.cli --root <包目录> rebuild           # 单包重建索引
python -m hma.cli --root <包目录> show <id>          # 打印某包完整 .md
python -m hma.cli --root <包目录> list              # 列出所有包
python -m hma.cli --root <包目录> ingest "<文本>"   # AI 主动收录

# —— hma.engine：检索/维护 ——
python -m hma.engine --root <包目录> query "<关键词>" --top-k 5   # L1 包级
python -m hma.engine --root <包目录> query_anchors "<锚点>"       # L2 章级锚点
python -m hma.engine --root <包目录> derive                       # 重派生锚点
python -m hma.engine --root <包目录> rebuild-all                  # 全仓重建 + 目录树
```

> **L3（取某章正文）不是 CLI 子命令**，由 MCP 工具 `memory_read_section`（`hma/server.py` 暴露）提供；L2 锚点定位后经它取正文。`query` 在 `hma.cli` 与 `hma.engine` 中均有，等价。
> **daylog 写入**走 `scripts/core/daylog_append.py`（单 daylog 路线，详见 `daylog设计.md`），无 CLI 子命令；读取经 `hma.daylog` 模块（`read_day` / `days_in_range`）。

### 2.1 压缩归档流程（compact.py · 上下文溢出 → 长期记忆）

触发：Agent 判定上下文窗口将满（主动加载），或用户说"归档/压缩/清理上下文"。与 ingest 的边界：ingest 管「新文本入库」，本流程专管「已发生讨论的溢出内容 → 卸到长期记忆」。

1. **收集溢出内容**：挑「已讨论完、暂未落库、值得长期留」的片段（不是一股脑全倒）。
2. **逐条判定落点（q-0 优先级）**：叙事/时间线 → 日志（daylog beat）；散碎暂无归属 → cache（`memory/cache/archive/<eid>.md`）；项目相关 → progress（项目包进度事件）。
3. **生成冷凝摘要**：每条 2~4 句自包含概述——**加法式冷摘要，原权威正文一字不动**。
4. **发现冲突**：query 扫现有包；新信息与权威事件矛盾时记该事件 id + 一句"改了什么"（默认不碰权威原文，仅真冲突覆盖）。
5. **确定性写（compact.py 三 sink）**：

```
python scripts/core/compact.py --root memory --sink <日志|cache|progress>     --summary "<冷凝摘要>" --source "<溢出来源>"     [--date YYYY-MM-DD | --id <eid> --title "<标题>" | --project <pid>]     [--linked a,b] [--tags x,y]     [--conflict-event <id> --conflict-intro "<一句话>"]
```

   日志 = `--sink 日志 --date 今天`（追加叙事 beat）；cache = `--sink cache --id <eid> --title`（落 `memory/cache/archive/`）；progress = `--sink progress --project <pid>`；冲突 = `--conflict-event`（**唯一改权威正文的口子，必须带 --conflict-intro 留审计 trail**）。
6. **回报**：逐条列 sink 落点与是否触发冲突覆盖 + trail。

纪律：内容即数据（加法冷摘要非销毁改写）；理解归 AI、确定性写归脚本；敏感内容不落 memory（工程红线 §4）。

### 2.3 召回失败诊断流程（三层手册 · 从便宜到贵）

原则：多数失败在前两层，改代码是最后一步且必须走沙箱。每条命令均已实测。

**第 0 步 固定最小失败用例**：写下查询原话/期望命中的包·锚点/实际返回。查询构造走理解层 AI 流（NL→实体词→per-entity query→合并），严禁整句+二元拆词当主路径（整串如「民法典32条」是单 token 会 no match）；用 scope 缩到目标子树排除跨树干扰。

**第一层 FM 字段**：`python scripts/core/scan_fm.py`（全库只读体检）+ `lint_memory.py --all`。人工核对：①知识真落盘了吗（没落盘先走收录，不叫召回失败）；②四要素漏填=漏召回（别名/描述表达式只进四要素变体 dict，绝不进锚点 keywords；斜杠式如「黄/橙」是含 / 的单变体 token）；③锚点 about 必须特征化（抽掉章名可与同包其他锚点互换=泛化，泛词互含→BM25 稀释→目标被挤出 top5，paper_camus P08 红基线即此违规）；keywords 5 维各 ≥1；④lint ERROR 必修，WARN 人工判断。

**第二层 index.db**：`python scripts/core/peek_index.py` 瞄索引；孤儿行检测脚本（FM 锚点数 vs index 锚点数比对）。判读：包不在索引=落 .md 后没 rebuild（最高频事故，rebuild 即愈）；孤儿行=测试污染（rebuild 清除，反复出现修测试清理逻辑）；FM 与 index 锚点数不一致=rebuild，rebuild 后仍不一致=引擎 bug 进第三层。复查：L1 query 确认有料再 read_section 看正文。

**第三层 代码流程**（前两层干净才轮到；先沙箱严禁同轮改生产，沙箱先例 MemorySandbox 子类模式）：①打印 normalize_terms(q) 看切分产物；②L1 打分与 waterfall_cut（相邻分差 >75 单向裁切，gold 掉队即记录）；③gate 层（coverage gate 需 ≥2 候选才启动，候选被上游饿死则 gate 永不触发；拒答四闸逐个看 reason）；④包级 BM25 rerank 默认关，重开必须先改锚点级；⑤对照历史病：先跑 regress 看是否旧病复发（law_demo/coverage_gate/paper_camus P08 各锁一个失败模式）。修复纪律：沙箱→展示→等确认→生产；新失败模式沉淀为 regress 用例；红基线不得洗绿。

**修复后必做**：改 FM→rebuild；改代码→14 项 regress 全绿且红基线保持原样；记 daylog beat；全新失败模式回诊断手册补一行。

### 2.4 路径定位与 MCP 部署协议（~/.hma_home · deploy_mcp.py）

1. 优先读指针文件 `~/.hma_home`（一行=仓库根绝对路径），指向目录含 memory/ → 直接用。
2. 指针缺失/失效 → 找 `scripts/core/where.py` 跑 `--json`（输出仓库根/memory/index.db/引擎 cwd，并自动登记 ~/.hma_home）。
3. 都不可得 → 问用户 HMA 解压位置，跑 where.py 登记。全程零路径推理，所有引擎命令 cd 仓库根执行。

**WorkBuddy MCP 连接器部署**（可选，让 mcp__aimh__* 工具可用）：`python scripts/core/deploy_mcp.py`——把启动器复制到 ~/.workbuddy/aimh_mcp_launch.py 并合并写出 ~/.workbuddy/mcp.json（只动 mcpServers.aimh，移除旧 hma 键，保留其它连接器；python 版本自动探测）。之后在 WorkBuddy 连接器管理页信任激活，新窗口出现工具。幂等可重跑；仓库搬家后重跑一次。

## 三、一键更新记忆索引.exe

- **位置**：仓库根 `一键更新记忆索引.exe`（与 `memory/` 同级），单文件 ~8MB，双击即用、零依赖。
- **做什么**：纯确定性重建——全量扫 `memory/` 下所有 `.md` 的 front-matter 重建 `index.db`。全程**零 AI、可随时重跑**（幂等）。
- **何时用**：
  - 手动路线：随手改 `memory/` 里的 `.md` 后，双击一下收敛索引；
  - AI 路线收尾：任何 AI 写操作后，由 `aimh-always`「收尾纪律」统一调它（或等效 `python scripts/core/rebuild_index.py`），与手动双击**同源**。
- **日志兜底**：无显示器/异常时写 `last_rebuild.log`；设 `HMA_NO_GUI=1` 强跳弹窗（调试/无头环境）。

## 五、双副本机制与调用约定

### 双副本
- 位置：用户级 `~/.workbuddy/skills/<name>/` 与 项目级 `skills/<name>/`（随开源）须 parity。
- 同步：AI **只在用户级**改一份 SKILL.md，然后跑一行命令镜像到项目级：
  ```bash
  python scripts/core/sync_skills.py push     # 用户级 -> 项目级 整目录镜像
  python scripts/core/sync_skills.py diff     # 只读校验双副本 parity
  python scripts/core/sync_skills.py new <名> [描述]   # 两侧各建最小骨架
  ```
- 纪律：确定性镜像归脚本，AI 不手改两副本（省 token，契合 AIMH 铁律）。
- **⚠️ `push` 是覆盖式复制，不删目标多出的目录**（`_mirror` 只遍历源、不清理目标）。故**项目级独有**的技能（当前为 `aimh-worldbook` / `aimh-obscure-recall`）**不会被 push 误删**，可放心跑。
- **⚠️ 备份文件不要进开源副本**：在用户级技能目录内留 `SKILL.md.bak-<时间戳>` 作回滚点是安全的，但**不要 `push` 镜像进项目级**（会污染随开源的目录）。此时 `sync_skills.py diff` 会把该技能报成 `DIFF`——**只要差异项是 `.bak` 就属正常**，用 `diff <用户级/SKILL.md> <项目级/SKILL.md>` 直接比对正文确认即可。

### 调用约定
- **确定性脚本永远不吃 token**：AI 只做理解（归类/拆分/关联判断），落库、建索引、装卸、重建索引一律交脚本。
- **路径自解析**：`rebuild_index.py` / 一键 EXE 自动定位自身同级的 `memory/`；其余脚本用 `--root` 或参数指定包目录。
- **可重建信仰**：`index.db` 是派生缓存，任何脚本（尤其 `rebuild_index.py`）都能由 `.md` 全量重建，索引丢了不慌。

## 六、聚焦检索（scope 旋钮）

> 对应《询问类型与解决思路》第 9 类（聚焦·arena）：AI 与用户围绕一个事件主题长期协作时，把检索**收束到该子树**，屏蔽其他记忆干扰、加速召回。它是叠加在各类询问之上的**正交 scope 轴**——不改变询问类型，只收窄候选集。

- **暴露位置（三处同源）**：
  - **引擎 API（Python）**：`Memory.query(q, scope=...)` / `query_anchors(q, scope=...)` / `resolve_query(q, scope=...)`，均默认 `None`=全仓，**零回归**。
  - **MCP 工具**：`memory_query` / `memory_query_anchors` / `memory_resolve` 各新增 `scope` 入参（字符串，留空=全仓）。
  - **CLI**：`hma.engine query / query_anchors` 当前**未接** `--scope`；命令行聚焦请走引擎 API 或 MCP。
- **用法**：`scope` 传**绝对路径**或**相对 memory 根的路径**（如 `项目/AIMH-design-journal` 或完整绝对路径）。引擎内部 `REPLACE(filepath,'\\','/') LIKE '%归一路径%'` 收束候选集；相对路径按 `os.path.join(root, scope)` 归一，故**勿传仓库相对 `memory/...`**（否则拼出双 `memory/` 失配）。
- **行为边界（红线）**：
  - 只收束**候选范围（scope）**，**不提升精度、也不替你拒答离题问题**——离题拒答仍归 AI 理解层（引擎 `allow_abstain` 闸门）。
  - 给定 scope 时引擎**抑制自动路由**（`routing.resolve_scope`），调用方已界定检索空间，避免路由包与 scope 冲突。
  - **逃生舱**：`scope=None`（或不传）即回到全仓，行为与旧版完全一致。
- **实测**（聚焦 `AIMH-design-journal`）：候选包 29→11（-62% 跨子树干扰）；该目录内相关问题全部命中、零越界；域外离题词仍由 AI 层 `allow_abstain` 判拒答。

> 检索（不写）走引擎 CLI：`python -m hma.cli query <root> "<词>"`（L1 包级）→ MCP 工具 `memory_query_anchors`（L2 锚点级）→ `memory_read_section`（L3 正文）。
> 相关：架构总览见 `什么是AIMH系统`；手把手使用见 `用户操作手册`。

## 七、技能骨架规范（2026-09-05 定稿）

技能 SKILL.md 的三层分工与压缩纪律（daylog-archive 试点定型，逐技能推广；本节为骨架惯例的唯一权威源）：

1. **三层分工**：召回卡（hook 常驻注入）= 全局硬约束；SKILL.md 骨架 = 判断性步骤序列 + 内联召回键；权威包（本目录各设计包）= 每步完整指引，**唯一事实源**。
2. **骨架步骤形态**：一句**判断** + 内联召回键（`["锚点名"]`）。分支判断的触发条件必须留在骨架里（不可再压的地板）；参数细节、边界条款、历史教训全部进权威包。
3. **ABSTAIN 即停**：召回键查询返回 ABSTAIN → 本步停止并报告，**勿即兴补流程**——「事实不编造」纪律扩展为「流程不即兴」。
4. **映射必须钉用例**：每个召回键 → 期望锚点，进 `regress_questionset.py`（T17-T20 daylog、T21-T23 ingest 为样板）；权威包改章节名/结构，骨架当场红。
5. **权威先行**：骨架引用的权威必须是超集——**先补包再压缩**（daylog 试点第 1 步曾发现包内示例块落后于 fail-closed 口径）。
6. **已有骨架不动**：aimh-intake（薄层路由器）自带「不要往里加步骤」守卫；aimh-recall 家族由召回卡覆盖——推广时逐技能判断，**不搞一刀切**。
7. **两族纪律勿跨技能复制**：写侧隐私（机密不进 memory）权威在《工程红线与自检纪律》§4；读侧私有包（C 类）权威在 aimh-always——技能内只留一行操作后果。
