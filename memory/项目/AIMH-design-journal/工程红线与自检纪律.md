# AIMH 工程红线与自检纪律

> 本包是 AIMH 三项工程纪律的权威存放点：**打分框架**、**测试纪律**、**Agent 自检**。
> 原暂存于工作区 `MEMORY.md` §四（AIMH 尚无对应包），2026-09-04 迁为独立包，使 MEMORY.md 退化为纯指针表。
> FM 字段契约见 `SCHEMA.md`；引擎 API 与检索机制见 `技术参考.md`。

## 1. 打分框架（scoring_coeffs 派生式）

唯一真相源 = `hma/scoring_coeffs.py`（A 锚点 / B 包级 / C 四要素 / D rerank / E 覆盖度 / F 分差 六组常数集中）。

- **BASE_UNIT = 150** 派生全档位：EXACT / CONTAINS / GARBAGE 三级、FIELD_IMP 字段加权，均从 BASE_UNIT 推导，不散落硬编码。
- **CUTOFF = 75 是 d_k「分差」基准（非绝对阈值）**：`d_k ≤ 75` 保留、`> 75` 掉队；瀑布式单向截断（`waterfall_cut`）。75 是分差，不是单包绝对分门槛——单关键词同实体不同包应同分（实测示例角色三包 300/300/300）。
- **覆盖度饱和 `1 - exp(-0.6n)`（SAT_K = 0.6）只落锚点级**：在 `_score`（`hma_core` L1171）/ `_anchor_score` 调用；**包级 `_score` 不加饱和**——避免下移误杀 + 牵动 75 裁切。饱和只落锚点级。
- **50 vs 75 对比实测**：Demo 20 题 floor = 50 / 75 均 20/20、0 题变化 → 阈值维持 75（更保守不误杀）。
- **rerank 装置是包级 BM25（非锚点级）**：`_bm25_corpus` 按整文件建 token 桶，同包所有锚点共享同一分，无法按锚点正文重排。当前默认关（`rerank=False`），重开 rerank **必须先改成 per-anchor body**，否则对同包多锚点无效且与 dK 裁切打架。
- **拒答 / 澄清四道闸已落产（非缺口）**：`_abstain`(L621) / `corpus_missing_entity`(L2466) / `read_section` auto_abstain(L4002+) / 多子问拒答(L4304) —— 这是向量 RAG 缺的护城河，盘点时勿再挂。

## 2. 测试纪律（known_gap 红基线不洗绿）

- **known_gap 红基线 = FM 锚点泛化铁律的违规检测器，非普通失败**：`known_gap` 用例（如 `paper_camus` P08）刻意标红，专抓「FM 锚点泛化」违规。它**不等同 FAIL、不得硬拉绿**；翻绿唯一合法条件是对应锚点 `about` 已改写成特征化摘要（违规已修），绝不是改测试断言。改绿却不改 about = 掩盖违规。
- **回归必须覆盖边界场景**：不能只跑 happy-path bench 就宣布绿。回归集须含：同包多锚点、keyword 分解宽/窄查询、对抗样本（5/5 拒答）。
- **对照 / 探针测试是正当任务**：用户说"再来个对照表 / B 组"即正式指令，必须执行，不得误读为越权。
- **金标准**：验证"通过"须来自独立权威源（`.md` front-matter 用 `from_markdown_fm_only` 抽取），不靠实现自身函数对账；走真实 MCP 路径（`server.dispatch`）。
- **召回测试走 AI 流**：主路径一律理解层 AI 流（NL → 实体词 → per-entity query → 合并排序），严禁 `query()` 整句 + `_reform_terms` 二元拆词当主路径。

## 3. Agent 自检（血泪纪律）

- **① 禁止自作主张加"保护 / 排序"层**：任何"保护 gold / 防 rerank 丢答案 / 原始分最高必须居首"类逻辑（OR-fail-safe、rule#1）**绝不自己写进 core**。dK 裁切自带保 gold 语义，再加一层 = 冗余 + 冲突 + bug。要加排序 / 保护逻辑，先问用户。
- **② 归因前必须读真实代码 + 跑真实复现，禁止凭记忆 / 脑补**：下结论前 grep / read 真实源码、用组合隔离（如 rerank × use_field_weights）定位。
- **③ 审查必须真 trace，禁止扫一眼说"没事"**：声称"通过"前必须跑沙箱、逐阶段打印中间状态（原始 scored → rerank → OR-fail-safe → rule#1 → 最终）用真实数据佐证。注释是自己写的、给自己圆，不可信。
- **④ 用户令"删 X / 关 X 跑测试"→ 真删真关 + 跑真实回归给数字**：删后 grep 悬挂引用 + `py_compile` + 跑 bench 给具体场景断言。
- **⑤ 删同类代码块须全仓 grep，绝不假定一处删净**：OR-fail-safe 曾在 `query_anchors` 与 `_body_aware_rerank` **两处**各出现一次，只删前者漏了后者。删完必须 grep 该类关键词（OR-fail-safe / fail-safe / rule#1 / base_top / pop 兜底）确认零残留再跑回归。
- **⑥ 错了直接认，不甩锅不绕**：误判就明说"我之前错了"，不编解释掩饰。用户要事实不要体面。
