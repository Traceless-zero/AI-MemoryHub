## 二、MCP server 详述

### 2.1 启动与部署

```bash
python -m hma.server --root memory      # 直跑
# 或 entry point：
hma-mcp --root memory
```

`stdio` 上的 JSON-RPC 2.0，仅实现最小子集：`initialize` / `tools/list` / `tools/call`。

**WorkBuddy 即插即用部署（推荐）**：仓库自带一键部署脚本，把启动器复制到 WorkBuddy 配置目录、合并写出 `~/.workbuddy/mcp.json`（只动 `aimh` 连接器、保留其它、自动探测 python 版本、不写死路径），并登记 `~/.hma_home` 指针：

```bash
python scripts/core/deploy_mcp.py            # 部署（幂等，可重跑）
python scripts/core/deploy_mcp.py --dry-run  # 只预览将写出的配置
```

启动器 `scripts/core/mcp_launch.py` 运行时读 `~/.hma_home` 指针 + 复用 `scripts/core/where.py` 定位 `memory/` 根，**不写死任何仓库绝对路径**；仓库搬家只需重跑一次 `deploy_mcp.py`。部署后在 WorkBuddy 连接器管理页点「信任」激活 `aimh` 连接器，新窗口即出现 `mcp__aimh__*` 工具。

> ⚠️ **长驻进程需重载**：`server.py` 改后，WorkBuddy 托管的 MCP 进程仍跑旧字节码。改完代码后需在连接器里禁用→启用 / 重新 Trust，新 `server.py` 才生效。

### 2.2 11 个工具完整清单

| 工具 | 必填入参 | 作用 |
|:---|:---|:---|
| `memory_write` | `id` | 原子写/改一个事件包（.md 权威源 + upsert 索引）；id 存在则覆盖 |
| `memory_query` | `q`,`keywords`,`mode` | L1 包级确定性检索，返回 Top-K 候选（命中唯一 ID） |
| `memory_query_anchors` | `q`,`keywords`,`mode` | L2 章级锚点检索，按 `##` 标题精确定位某轮/某节（返回 locator=Chapter 标题） |
| `memory_resolve` | `q`,`keywords`,`mode` | 召回消歧统一入口：命中≥2 实体时澄清，否则返回 Top-K；支持 multihop + 拒答闸 |
| `memory_read_section` | `id`,`heading` | L3 取正文：按 (id, heading) 只读该 `##`/`###` 段，零冗余 |
| `memory_link` | `a`,`b` | 双向关联两个事件包（更新两者 front-matter 的 `linked`） |
| `memory_rebuild` | 无 | 从所有 `.md` front-matter 全量重建 index.db（.md 是权威源，不丢数据） |
| `memory_ingest` | `text` | 主动收录：用户贴文本，AI 跑完整管线（理解拆分 → 写 .md + 索引 → 关联） |
| `memory_aggregate` | `unit` | 计数问（Type 8）：结构化计数器，unit ∈ packages/events/persons/locations/topics；支持 filters / event_date_like / scope / return_list；结构化入参、绝不透传 raw SQL |
| `memory_time_filter` | `time_hint` | 时间硬过滤（Type 6）：解析模糊时间语（"前天/去年10月"），返回月级命中的包列表；时间只是过滤键，不做新鲜度加权 |
| `memory_obscure_recall` | `q`,`obj_token` | 细节追问：不起眼物件 context-scope 三态锁章（explicit/reading/global），章内局部倒排定段；路线一无果自动拒答、转路线二 C+A 卡片交人终审 |

### 2.3 各工具入参明细

**`memory_write`**
`id`(str,复合路径不含.md) · `title` · `summary` · `tags[]` · `linked[]`(复合 id 含.md) · `body` · `pkage_created`/`pkage_updated`(YYYY-MM-DD) · `person{}`/`location{}`/`topic{}`(规范名:[变体]) · `anchors[]`({Chapter,about,keywords}) · `event_date`(YYYY-MM-DD/YEAR-YEAR/`—`)

**`memory_query` / `memory_query_anchors` / `memory_resolve`**（三者共享检索型入参）
- `q`(str,必填) — 归约后的核心查询句
- `keywords`(str[],必填) — AI 解析出的复合实体词，**驱动 `corpus_missing_entity` 硬拒答闸**
- `mode`(str,必填) — `single`/`multi`/`enumerate`（见 §2.4）
- `top_k`(int,默认 5)
- `scope`(str,可选) — 聚焦检索子树路径
- `multihop`(bool,默认 false) — 沿 linked 双向 BFS 扩簇
- `allow_abstain`(bool) — `query_anchors`/`resolve` 专有，默认 true（开启拒答层）
- `allow_clarify`(bool) — `resolve` 专有，默认 true（多实体时澄清）
- `raw_query`(str,可选) — 原句审计留档
- `sub_queries`(str[],可选) — `multi` 模式必填：AI 已拆好的子问清单

**`memory_read_section`** `id`(必) · `heading`(必,##/### 标题包含匹配)
**`memory_link`** `a`(必) · `b`(必)
**`memory_rebuild`** 无参
**`memory_ingest`** `text`(必) · `scope` · `provider` · `model` · `auto_link`(默认 true)

**`memory_aggregate`** `unit`(必,packages/events/persons/locations/topics) · `filters{}`(列:(算子,值)) · `event_date_like`(便捷封装 event_date 前缀模糊) · `scope` · `return_list`(默认 false，true 时枚举实体) · `top_k`(默认 500，硬上限 500)
**`memory_time_filter`** `time_hint`(必,模糊时间语) · `scope` · `top_k`(默认 500)；解析不到时间意图 → 返回空
**`memory_obscure_recall`** `q`(必) · `obj_token`(必,追问的物件词) · `package_id` · `scope_chapter`(显式锁章名) · `scope_mode`(explicit/reading/global，默认 reading) · `top_k`(默认 5) · `window`(默认 200 字符)

### 2.4 QueryEnvelope 调用契约（MCP 边界强制）

每次检索类调用（query / query_anchors / resolve）都被 `hma/envelope.py` 的 `QueryEnvelope` 校验层拦截。**违反契约直接返回 `ENVELOPE_VIOLATION` 阻挡，不进引擎**——把「AI 漏传 keywords / 乱填 mode」这类软错误提前在边界挡死。

```
QueryEnvelope:
  q:          str            # 必填。归约后的核心查询句（长难句须先 reduce 再分类）
  keywords:   list[str]      # 必填。从【原句】抽取实体/上下文词；corpus_missing_entity 硬拒闸的唯一输入
  mode:       "single"|"multi"|"enumerate"   # 必填。查询意图分类
  scope:      str | None     # 可选。聚焦 arena（enumerate 必带）
  allow_abstain: bool        # 默认 True。开启拒答闸
  multihop:   bool           # 默认 False。沿 linked 扩簇（multi 下的分解手法）
  raw_query:  str | None     # 可选。原句审计留档（与 q 的归约句区分）
  top_k:      int            # 默认 5
  sub_queries: list[str]     # multi 必填：AI 已拆好的子问清单
```

**硬约束（校验失败即 `ENVELOPE_VIOLATION`）**：
1. `q` 非空；
2. `mode ∈ {single, multi, enumerate}`（传 `union` 等非法值会被挡）；
3. `keywords` 非空——它是**最强拒答闸的唯一输入**，漏传会退化成弱闸、复合实体无法硬拒；
4. `mode == "multi"` ⇒ `sub_queries` 非空（拆问归 AI 理解层，引擎不内置拆问）；
5. `mode == "enumerate"` ⇒ `scope` 非空（无 scope 即无枚举对象）。

**调用铁律**（写进 `aimh-recall` 技能）：
- 长难句先**归约**再分类：`query` 装归约后核心句，`keywords` 从**原句**抽，`mode` 永远判在归一句上；
- 多问题 = 拆碎多次查，AI **一次给全 `sub_queries` 清单**，不单独往返调用（每多一轮 AI 侧往返就多一份漏合并/前后不一致风险）；
- 多跳不是独立 mode，是 `multi` 下「沿 linked 扩散」的分解手法（置 `multihop=true`），opt-in；
- 违反任一必填 → 调用被挡回，按提示补 `q`/`keywords`/`mode`/`sub_queries`/`scope` 重发。

## 三、引擎 Memory API

`hma/hma_core.py` 的 `Memory` 类（零运行时依赖，仅标准库）。所有方法直读/直写 `memory/`，权威源为 `.md`，索引可由 front-matter 全量重建。

```python
from hma.hma_core import Memory
m = Memory("memory")

# 写入与关联
m.write(id, title="", summary="", aliases=None, tags=None, linked=None, body="",
        created=None, updated=None, pkage_created=None, pkage_updated=None,
        anchors=None, embedding=None, trigger=None, person=None, location=None,
        topic=None, event_date=None, features=None, record_change=True,
        integrity_check=False, force_empty_body=False)
m.link(id_a, id_b)
m.check_write_integrity(target_ekeys=None, soft_k=3)   # 写入侧反推：检测缺乏独有弧段的实体

# 检索漏斗
m.query(q, top_k=5, use_vector=False, package_id=None,
        keywords=None, decomposer=None, scope=None)
m.query_anchors(q, top_k=5, package_id=None, dedup_packages=False,
                idf=True, package_agg=False, rerank=True, reform=True,
                use_field_weights=True, use_features=False,
                allow_abstain=False, kappa=None,
                context=None, decomposer=None, keywords=None, scope=None)
m.resolve_query(q, top_k=5, use_vector=False, package_id=None,
                allow_clarify=True, multihop=False, scope=None,
                keywords=None, decomposer=None, allow_abstain=False)
m.recall_multihop(q, top_k=5, max_hops=2, package_id=None,
                  keywords=None, decomposer=None)

# 取正文 / 重建
m.read_section(id, heading)
m.rebuild()                       # 重建【当前包】索引
m.derive_anchors(text, max_level=6)   # 扫描 ##~###### 树确定性派生章级锚点（写入侧细切全层级）

# 多问扇出 / 枚举（QueryEnvelope 模式支撑）
m.orchestrate(sub_queries, top_k=5, keywords=None, scope=None, allow_abstain=True)
m.list_all_in_scope(scope=None, top_k=None)

# 特征重叠匹配（理解层 L1.5）
m.query_features(q, top_k=5, min_hit=2)
```

> 注意：`query()` / `query_anchors()` / `resolve_query()` 的 `scope` 入参已在 V0.5 后 port 进生产（默认 `None` = 全仓零回归）；`orchestrate` / `list_all_in_scope` 为本次 session 新增。Python API 直接调用**绕过 MCP 边界**，不受 QueryEnvelope 约束——这是预期隔离（测试/编排脚本走 API 不受影响）。
>
> **`allow_abstain` 默认值分层**：Python API 层默认 `False`（`query_anchors`/`resolve_query` 直接调用不拒答，测试/编排脚本零干扰）；**MCP 层默认 `True`**（server.py 对 `allow_abstain` 缺省视为 True，用户侧拒答层默认开启，防编造）。文档若说"默认 True"指 MCP 工具行为，Python API 默认是 False。

## 六、召回颗粒度与锚点派生

检索漏斗分三级：
- **L1 `query`** — 定位包（~22 字摘要），在 id/title/alias/tag/summary 上关键词匹配
- **L2 `query_anchors`** — 定位子事件（章），返回定位键 Chapter = `##` 标题
- **L3 `read_section(id, heading)`** — 只读该 `##` 段正文

实测（demo-origin 28542 字样本）：漏斗 payload 4831 字 → 较 origin 包省 83.1%、较整库 35503 字省 86.4%。

**召回单元为 `##`~`######` 层级标题（写入侧细切）**：`derive_anchors` 默认 `max_level=6`，取 `##`~`######` 全层级生成章级锚点——章节层级细的文档（如论文 `##`/`###` 小节）自动获得更细锚点，读取侧按 `read_section` 只读对应段、成本最小化。层级过细导致内容被切断属原文文档本身结构问题，非检索侧责任。

**锚点自动派生器（已实现）**：`derive_anchors(text, max_level=6)`（经 `python -m hma.engine derive <root>` 命令式调用）扫描 `##`~`######` 标题树 → 生成章级锚点（Chapter = 标题原文、`summary` = 章首句、可全量重建；front-matter 契约锚点为 {Chapter, about, keywords}，无 `locator`/`title` 字段）。仅定位「哪一章」，不切分；确定性、OC 无关、不依赖 LLM。
- 构建时自动派生：`packs` handler 在包未显式给 `anchors` 时从正文 `##` 树自动派生。
- 命令式回填：`python -m hma.engine derive <root>` 幂等——再派生与正文一致则跳过、不产 changes 噪声。

## 七、检索机制详解

### 7.1 scope（聚焦检索）
正交轴，叠加在 1–9 类询问之上，只收敛候选集（`REPLACE(filepath,'\','/') LIKE '%归一路径%'`），**不提精度、不替拒答**。默认 `None` = 全仓零回归。实测全仓 29 包 → 聚焦 `AIMH-design-journal` 11 包，跨子树干扰归零。给定 scope 时抑制自动路由，避免路由包与 scope 冲突。

### 7.2 abstain（拒答层，V1.0 已落地）
四道确定性闸门：`_abstain()`（空池 / 覆盖不足 / 四要素越界 / 零重叠）+ `_out_of_scope()` + `corpus_missing_entity` 反相硬闸（传入 `keywords` 时，判别实体在语料查不到则拒答）。阈值 `ABSTAIN_KAPPA=0.34` / `ABSTAIN_HIGH_K=0.67`。MCP 工具 `allow_abstain` 默认 True，handler 返回 `(ABSTAIN: <reason>) 记忆中无匹配，请勿编造`。Demo mini-bench 对抗 5/5 正确拒答；bench G7 域外 abstain 10/10、leak=0、over_refusal=0。

### 7.3 multihop（沿 linked 扩散，opt-in）
`recall_multihop` 三路播种 → `_linked_adjacency()` BFS（`max_hops=2`）→ 簇内打分（own 自有锚点分 / link-boost 直接相邻种子分 / 命名命中 +1e6）→ `(-score, hop, rid)` 确定性排序。补的是**全局关键词搜索的关系/结构盲区**（如「谁设计拒答层 → 他其他作品」只在 `linked` 边里）。是**确定性图遍历，非向量 graph-RAG**——依赖写入时策展的 `linked` 边，受「连边完备度」约束。纯事实单实体问多跳是纯噪声，故默认不开。

### 7.4 sub_queries（orchestrate 扇出，multi 模式）
`mode="multi"` 时 AI **一次性**给 `sub_queries` 清单，引擎 `orchestrate()` 循环 `query_anchors` 各子问、按子问分组返回、跨子问按 `(pkg_id, anchor_title)` 去重。把「多次往返调用」的出错面收敛成「一次结构化输出 → 引擎机械执行」。引擎**不内置拆问**（CEMA：理解前置到 AI 侧）。

### 7.5 enumerate（list_all_in_scope）
`mode="enumerate"` 路由到 `list_all_in_scope(scope)` —— **确定性 `ORDER BY filepath` 列出 scope 子树内全部包**（非 Top-K 相关度排序），`scope=None` 退化全仓。弥补「范围·枚举问题」无专门返回形态的缺口。

### 7.6 覆盖门（软·强信号快捷通道）
`resolve_query` 在**实体去重 / 歧义门 / 澄清之前**先判『区分词能否唯一锁定候选』：查询 token 中**仅命中 top-K 候选恰好 1 个**者即区分词（如 `纯净蓝` / `孤品` / `2005`）；若全部区分词指向同一候选 → 直接 `return`（`stage=coverage_gate`，附 `discriminators` 区分词清单），跳过澄清；无区分词或区分词分裂 → 回落既有歧义门。**软门非硬 AND 过滤**——不要求所有词必中（防 over-abstain / paraphrase 删空），误杀 0。
- 区分词检测范围 = 召回 top-K 池（`top_k×2`）；匹配用包级可检索 blob 的**连续子串**（不做 CJK 二元扩展，避免 `纯蓝` 误中 `纯净蓝` 被当区分词）。
- 定位：F+C+A+READ 的「能否不问就定」检查——澄清红利的自动化：top-K 已含答案时强区分词直接把用户送到底，只有真正需要挑时才进澄清门。
- 沙箱原型验证（2026-08-20）：唯一召回 100% / 误杀 0 / paraphrase 安全；生产回归锁 `scripts/tests/regress_coverage_gate.py` 10/10。

### 7.7 澄清门卡（`#`下钻 · 读取侧铁律）
`resolve_query` 判 `clarify` 时，MCP 坍缩层（`_h_resolve`）把命中锚点当 **`#` 下钻令牌**呈现，而非整包标题——否则「示例信物」只显示为「示例角色 · 背景故事」，用户难把标题与「那颗黄橙双色宝石」对上号。复用 AIMH 既有 `#` 约定（`daylog#NN`、`read_section` 按 `##`~`######` 定位）。三机制：
- **① 形态 `#<叶锚点>`**：候选以 `#示例事件` 出现，配 `about`（明写「示例信物盗窃案」），用户一眼接上实体。
- **② 叶优先**：同包多锚点命中只取**标题层级最深**那个（`### 示例事件`），消解「哪个锚点触发」的纠结；依赖 `derive_anchors(max_level=6)` 已派生 `###` 级锚点（§六 已对齐，非白皮书旧说只 `##`）。
- **③ 非实体直读正文**：无独立实体包的对象（示例信物仅作 demo-origin 的 topic 变体 + 锚点引用 + 正文描写），选中门卡后 `read_section(示例事件)` 让 AI 读正文，不造假实体包。
- **铁律**：门卡 = `#叶锚点` + `about` surfacing；选中即 `read_section` 直读。**澄清红利的 UX 闭环**——top-K 含答案时把候选收口到结构化 `#锚点`（非文本模糊团），挑一个即廉价确认。
