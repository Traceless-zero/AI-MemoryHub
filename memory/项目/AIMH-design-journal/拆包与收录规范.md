# 拆包与收录规范（集中汇编总入口）

> 本文件是 AIMH 各类记忆包**拆包与收录**的集中汇编：通用收录流程、各内容类型的拆包实操、鸿篇巨制单包上限、跨类型对照表。
> **契约权威源 = `SCHEMA.md` §4（命名空间与拆包契约）**；**机制权威源 = 各技能/设计文档**（`oc-dossier` / `aimh-project` / `daylog设计.md` / `存储架构总览.md`）。
> 本文件**不重复定义规则、只提炼与索引**，避免与权威源漂移。新增内容仅 §7 鸿篇巨制拆包（此前只在对话中定方向，现落文）。

## 1. 总纲（CEMA + 单包规模控制）

- **CEMA**：AI 理解层负责拆包判定与字段归一；确定性引擎（`Memory.write` / `scripts/`）负责落库与索引。理解前置写入时。
- **单包规模控制是硬约束**：单包不应无限膨胀。拆包触发条件是**凝聚性 + 体积**，不是作者写法运气（见 §3）。鸿篇巨制另有单包上限（§7）。
- **命名空间目录硬隔离**：用户 / 项目 / 原创角色 / 日志 / 对话 / 其他 / cache 各自独立 store，落点见 `SCHEMA.md` §4 表。
- **front-matter V2 是所有包的落库契约**：11 必填字段齐备、四要素 dict、anchors `{Chapter,about,keywords}`、变体归一、禁写 `id/aliases/features/created/updated`。细节见 `SCHEMA.md` §2。

## 2. 通用收录流程（aimh-ingest 三段 + 路由）

通用分支（零散文本 / 笔记 / 用户自身数据）→ `aimh-ingest`；成体系对象（项目 / OC / 对话 / 文章）走专用技能，但都遵守同一套路由判定（`SCHEMA.md` §4.4）：

1. **判命名空间**：用户 / 项目 / 其他 / OC / 日志 / 对话。
2. **判模块**：内容语义命中哪个默认模块（用户→五模块；项目→README 式功能模块；…）。
3. **比对 index**：该包是否已存在？
   - 存在且同物 → **增补/覆盖同包**（update，不新建）。
   - 存在但过大（体积触发） → 在该模块下拆子包 / 子事件 id。
   - 不存在 → 仅当凝聚性成立，按嵌套逻辑关系新建。
4. **严禁**：把不同模块内容塞进一个包；为小内容预建一堆空模块包。

### 2.1 移包与合并（收录纠错 · relocate_package）

收录钩子（ingest 第 6 步）两个纠错关键字「移包 <目标>」「合并 <已有包>」的执行流程——理解归 AI（判定操作类型/源/目标），**搬家纯确定性**（绝不重写 .md 正文、不重新拆包、不调 LLM 落库）：

1. **解析意图**：操作类型（移包=改路径/改名；合并=并入已存在包）；源包=刚收录的包（回看收录钩子报告的 package_id，拿不准就问）；目标=用户给的新路径或已存在包名（只说短名时用 query 解析完整 package_id）。
2. **执行（二选一，在仓库根）**：
   - 移包：`python scripts/core/relocate_package.py <memory_root> "<src>" "<dst>"`——搬整目录 + 删旧索引及子孙 + 新位置逐包重挂；**拒绝覆盖已存在目标**（防误并包）。
   - 合并：同命令 + `--merge`——src 全部事件 .md 移进已存在的 dst + 删 src 索引 + 重挂 dst + 清理 src 空目录；**dst 不存在则退化为移包**（改用移包）。
3. **回报 + 核对**：脚本输出清单原样回报；`query <root> "<关键词>"` 核对 dst 现含全部事件、`linked` 跨包仍按 id 生效。

铁律：**只搬家、不重造**（不重写正文/不重拆/不调 LLM）；移包拒绝覆盖已存在目标；合并要求 dst 已存在。

## 3. 拆包触发铁律（凝聚性 + 体积）

对应设计原则「活文档整合 / 无限拆分」——**拆包触发条件是体积/凝聚性，不是作者写法运气**：

- **不提前拆小东西**：小内容硬拆成独立包 = 索引碎片化、检索噪音、维护成本上升。小内容先作同包内不同事件 id。
- **过度拆分信号**：一个包只有一两句、或模块间高频互链成网状 → 应合并或升级为更高阶包。
- **体积触发拆子包**：单包正文超阈值（见 §7 鸿篇巨制上限；常规包以「可读/可维护」为感性阈值）时，在同模块下拆子包或子事件 id。

## 4. OC 拆包（oc-dossier 三层铁律）

落点 `memory/原创角色/<char>/`，三层铁律切片（structured→`dossier_build.py` 自动切片；ambiguous→AI 按铁律抽取；两路出口一致）：

1. **基础包（必有，仅 1 个）** = 姓名 + 形象 + 语气/调性（`{id}-base`）。AI 能基本扮演的最小可运行单元；无论 OC 多浅多深永远只有 1 个包。
2. **origin 包（背景故事包，默认必有）** = 人物背景故事，**无论长短独立成包**（`{id}-origin`）。哪怕一行字/一句短语也单独拆出；仅确实无任何背景故事者省略。长叙事**原样收录、禁止综述化/压缩**，细粒度召回靠锚点而非切碎文件。
3. **拓展包（有则分）** = 感情/关系/战衣/武器/能力/信条…，只在存在时分立（`{id}-ext`）；极简 OC 可无拓展包。

**不可违反**：一个角色一个基础包（不得拆姓名/形象/语气）；不动用户 OC 源文件（抽取走读副本）。唤醒只读不写：从 `base_id` 启动，问起源→origin 包惰性召回，问能力/关系→ext 包 `read_section`。

**纪律**：结构化工程跟踪进项目包、不进 daylog（daylog 只写一句大事件+linked）；模块是默认路由指南非强制；嵌套逻辑可放心嵌套（引擎子孙检索已支撑）。

### 5.1 预建骨架与确定性生成（2026-09-05 自 aimh-project 收编）

- **新建项目包默认骨架预建 4 个状态模块**：`需求清单.md` / `项目结构.md` / `约定.md` / `架构.md` 一次性建好（可空壳：`# 标题` + 引言占位）——这是项目的"标准收纳格"，后续内容按模块归位，不为小内容临时起新包。`开发日志.md` **不预建**：首次有 beat `linked` 指向它时由派生脚本生成。
- **确定性生成（推荐）**：`python scripts/core/new_package.py --module-set 项目 --path memory/项目/<项目名> --project <项目名>` 一次性建齐四包（四模块互链、已存在自动跳过绝不覆盖、含 rebuild 提醒），格式零手搓。
- **与 aimh-ingest 通用分支的边界**：零散文本 / 笔记 / 用户自身数据走 ingest；**成体系的项目工程对象**走本节流程。
- **README 式 vs 子系统切的区别**：子系统切是**实现视角**，README 式是**读者视角**——新人先想"要做什么（需求）、长啥样（结构）、怎么变的（日志）、啥规矩（约定）"。

### 5.2 收录六步流程（完整步骤）

1. **定位 root**：`memory/项目/<项目名>/`（`<项目名>` 用用户给的或推断的中文名）。
2. **判模块 / 比对 index**：跑 `python -m hma.engine query <root> "<项目名>"` 看该项目包是否已存在；存在则**增补**对应 md，不存在则按上方结构新建（含默认 4 状态模块骨架）。
3. **按模块落库（每个 md 一个包）**：推荐**直写 `.md`**（按 SCHEMA.md §2.8 范本写 FM + 正文，落 `memory/项目/<项目名>/<id>.md`），或等价调用：

```python
Memory(root).write(
    id="<项目名>-需求清单", title="<项目名> 需求清单", summary="<2~4句自包含真概要>",
    tags=["project", "<项目名>", "需求"],
    person=[...], location=[...], topic=[...], event_date="—",
    anchors=[{"Chapter": "...", "about": "...", "keywords": [...]}],
    created="<pkage_created>", updated="<pkage_updated>", body="<正文>")
```

   ⚠️ **不要用 `python -m hma.cli ... write`**：其旗标无法携带四要素 dict 与 `pkage_created`/`pkage_updated`，会丢字段——与 aimh-ingest 口径一致，仅极简包可例外。项目结构 / 约定 / 架构 同法（id 分别为 `<项目名>-项目结构` / `-约定` / `-架构`）。正文用 `##` 分节，`##` 即 L2 锚点。
4. **互链（按需）**：需求 / 日志 / 约定 / 架构之间真相关才 `link`，不编造 id。
5. **记 daylog + 重建索引**：daylog 是唯一事件流权威源，`开发日志.md` 只是派生主题视图——**永不手写**。本次收录追加一条起包 beat（`--linked "项目/<项目名>/需求清单"`）；后续工程改动的详实内容同样写当天 daylog beat（`--linked "项目/<项目名>/开发日志"`），派生脚本自动聚进开发日志.md。落库后跑 `python scripts/core/rebuild_index.py --no-gui`（否则包在磁盘但检索层隐形；经 daylog_append 写入则收尾自动重建）。
6. **回报（含归类开口）**：列出建了哪些 md / 落点；若项目名是推断的，带固定句式：「**当前归类为 `<项目名>`，如有异议可以切换为 `<次优候选>`（一句话理由）**」。用户答"换"即跑 `python scripts/core/relocate_package.py memory "<路径A>" "<路径B>"`。

### 5.3 模块路由判定（落点决策，配合步骤 2 比对 index）

1. **判命名空间**：项目 → 落 `memory/项目/<项目名>/`。
2. **判模块**：内容语义命中哪个 README 式功能模块（需求清单 / 项目结构 / 开发日志 / 约定 / 架构）。
3. **比对 index**：该模块包是否已存在？存在且同物 → **增补/覆盖该包**（update 同包不新建）；存在但过大（体积触发）→ 该模块下拆子包/子事件 id；不存在 → 仅当凝聚性成立按嵌套逻辑新建（标准 4 模块已默认预建，一般只需补内容）。
4. **严禁**：不同模块内容塞一个包；小内容硬拆独立包（4 状态模块骨架允许空壳占位）；手写 `开发日志.md`。

### 5.4 front-matter 规范（落库必填）

必填 11 字段（title、summary 2~4 句真概要、tags 2-5、linked 复合 id、四要素 person/topic/location 规范形态 list 包裹 [{规范名:[变体]}]、event_date、pkage_created/pkage_updated；完整契约与照抄范本见 `SCHEMA.md` §2）；`id` 仅作 .md 文件名 slug（**非 FM 字段**）。anchors 唯一形态 `{Chapter, about, keywords}`（显式写、满足 5 维；不留空让引擎盲派）；无 `created`/`updated`，统一 `pkage_*`。正文以 `# 标题` 开头，`##` 即子事件锚点。

## 6. daylog（事件流权威源 · 不拆包、追加式单文件）

落点 `memory/日志/daylog-YYYY-MM-DD.md`，一天一份、日期即主键。**daylog 走的是「单文件追加」而非「拆包」**——它是唯一事件流权威源，当天事件详实内容只写这里、写完冻结只增不改：

- **AI 写入零路由**：只向当天 daylog 追加一条 beat（`### NN·标题·HH:MM` + `touched` + `<!--beat linked/tags-->`），不做归置判断。
- **主题视图派生**：`derive_topic_views.py` 扫 beat 按 `linked` 聚合，机械重生各包 `开发日志.md` 与全局 `主题索引.md`（带「本文件由脚本派生」标记、禁手改、可重建）。
- **起包规则**：一次性内容永久留 daylog 不搬家；同一 tag ≥3 天出现 → 主题索引列起包建议（脚本给建议、用户定）；起包后旧条目不回搬，新 beat 的 `linked` 改指新包。
- **双轨**：事件进 daylog（权威过程）、作品进主题包（权威结论），靠 beat `linked` 互指。

## 7. 鸿篇巨制拆包（新增 · 单包上限）

**问题**：单包不应无限膨胀。实测《战争与和平》级（~361 章）的 front-matter（含 anchors）可达 ~60KB，逼近读取侧上限；且单包锚点越多，L2 选章信号越稀释、人越难读、写入原子替换风险面越大。

**方案（收录阶段控规模，契合 CEMA 理解前置）**：

- **结构件独立成导航包**：序言 + 目录 + 后记等非正文结构件 → 独立成「导航包」（如 `<作品名>-导航`），`linked` 到各正文包；导航包只承载定位与全局脉络，不承载章节正文。
- **正文设单包上限**：单包正文建议上限 **~2–5 万字/包**（对应 ~20–60 锚点）。
  - **拆分粒度优先级**：按卷/部自然边界优先（如「第一卷」「上部」各一包）；无自然边界则按字数窗口切（窗口末尾尽量落在章/节边界，不切断语义段）。
  - **四要素继承**：各正文包子包的 `person`/`topic`/`location` 继承父作品实体；`event_date` 用作品时间跨度（`YYYY-YYYY`）或单点。
- **四维收益**：召回精度↑（小包 L2 锚点稀释少）、人可读↑（逐包维护）、索引 I/O↓（单包 FM 几 KB 不触发 fallback）、写入安全↑（小包原子替换风险面小）。

**读取侧配套（兜底，非替代）**：`_load_for_index` 头部读取上限已提至 **1MB**（`hma_core.py`），可吞下《战争与和平》级 FM 仍留 16x 余量；即便超界也由 `if not pkg.anchors` 全量回退保证正确。读取侧魔数是兜底，写入侧控包大小才是治本。

> ⚠️ **状态**：本段为草案。单包上限具体值（2–5 万字）、是否实现自动切分（aimh-ingest 判定 + 确定性按卷/字数切分）待用户确认后落地。

## 8. 对话 / user / 文章 拆包（速览）

- **对话记录**（`memory/对话/<主题或会议名>/`）：每场会议/对话**独立成包**；`summary`=背景，`##对话原文`=逐字 transcript，`##关键内容`=拍板决定；anchors 用 C+A 双锚点（对话原文/关键内容各带定位）；`tags` 由 `##关键内容` 派生（单一真相源）；矛盾不静默覆盖、每场独立成包。
- **user 五模块**（`memory/用户/<模块>/`）：主语必须用户本人；默认 偏好/方法论/身份锚点/踩坑/事实 五凝聚模块；小内容先作同包内事件 id，不硬拆独立包。
- **文章/资料**（`memory/其他/`）：`<主题>-orig` 原文包 + `<主题>-review` 综述包互链（原文存全量、综述存理解层摘要）；cache 为 `aimh-archive` 溢出兜底 `memory/cache/archive/<eid>.md`。

## 9. 跨类型拆包对照表

| 类型 | 落点 | 拆法 | 铁律 |
|---|---|---|---|
| OC | `原创角色/<char>/` | 基础包(必有仅1)/origin(默认必有)/ext(有则分) | 长叙事原样收录不切碎；一个角色一基础包 |

| 文章 | `其他/` | orig+review 互链 | 原文全量/综述摘要 |
| 鸿篇巨制 | 按卷/部拆多包 + 导航包 | 结构件独立导航包；正文 2–5 万字/包 | 写入侧控规模（草案） |
