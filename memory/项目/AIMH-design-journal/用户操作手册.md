# AIMH 用户操作手册（手把手 + 端到端流程 + 读写机制）

> 手把手带你在本地把 AIMH 跑起来，并走通一次"收录 → 召回"的完整链路；最后解释读写底层机制（features 三流 / 三级询问）。

## 〇、前置：零依赖与环境

- AIMH 引擎**零第三方依赖**（`pyproject dependencies=[]`）：核心检索是确定性 BM25 + 词法 rerank，不依赖向量/ML 框架。
- 运行入口：托管 Python（3.13.x，WorkBuddy 托管发行版或任意标准 Python 3.10+）；需第三方包（如 LoCoMo 的 openai/torch/transformers）时改用项目 venv 的 python.exe。
- 仓库根会自动登记到 `~/.hma_home`，`aimh-*` 技能 / MCP 启动器据此免路径推理直接定位记忆库。

## 一、两个命令行入口

AIMH 提供两套互补的命令行入口（均直读/直写 `memory/`，`.md` 权威源、`index.db` 可重建）：

- **`hma.cli`**（`python -m hma.cli`）：写/链/列/显/收录类——`write` / `link` / `rebuild`(单包) / `show` / `list` / `ingest` / `query`。
- **`hma.engine`**（`python -m hma.engine`）：引擎检索/维护类——`query` / `query_anchors`(L2 章级) / `derive`(重派生锚点) / `rebuild-all`(全仓) / `install`/`uninstall`(装卸包索引) / `modes`。

> `tree` 已停用；`daylog` 已从 CLI 卸除（走 `scripts/core/daylog_append.py`）。L3（取某章正文）不是 CLI 子命令，由 MCP 工具 `memory_read_section` 提供。

## 二、端到端流程 A–J（写→链→召回）

- **A. 收录**：把文本/对话/文章写进记忆（走 `aimh-ingest` 技能或 `hma.cli write`）。
- **B. 拆解**：Agent 把输入拆成"凝聚性事件包"，定四要素（person/event_date/location/topic）、tags、linked。
- **C. 规范**：按 SCHEMA.md 统一 front-matter；别名/同义词进变体数组（无独立 aliases/features 字段）。
- **D. 落库**：`python -m hma.cli --root memory/<scope> write ...`（或 `Memory(root).write(...)`），引擎自动派生章级锚点 `##`、刷新统一索引。
- **E. 关联**：`link A B` 建立双向关联，召回时沿 `linked` 扩簇。
- **F. 重建**：`rebuild`（单包）/ `rebuild-all`（全仓）/ 双击 `一键更新记忆索引.exe`（全仓重建 + 锚点自动派生，幂等）。
- **G. 召回**：`query "<词>" --top-k 5` 包级（L1）；`query_anchors "<锚点>"` 章级（L2）。
- **H. 取正文**：用 `query_anchors` 返回的 Chapter 标题，调 `memory_read_section` 取某章正文（L3）。
- **I. 校验**：写入后加 `--integrity-check`，引擎返回 `{path, warnings}`；若 `warnings` 非空说明实体缺乏独有弧段，须反推补独有关键词。
- **J. 维护**：`relocate_package.py` 归类纠错（搬迁/合并）；`sync_skills.py` 技能双副本同步；`pdf_reflow.py` 论文归档重排。

## 三、读写底层机制：features 三流 / 三级询问

- **features 三流**：
  1. **写入流（CEMA 落库）**：Agent 理解 → 确定性脚本写 `.md` + upsert 索引。
  2. **索引流（front-matter → index.db）**：薄索引只存 front-matter 派生字段，可随时全量重建。
  3. **理解流（Agent 理解层）**：只做消歧/关联/REFINE，不碰存储。
- **三级询问**（与三级漏斗对应）：L1 包级询问（缩圈）→ L2 章级询问（定位章）→ L3 正文级询问（取正文），逐级收窄、按需取用，不在召回早期拉全量正文。

## 四、常见任务速查

| 想做 | 命令 |
|---|---|
| 新建事件包 | `python -m hma.cli --root memory/<scope> write --id X --title T --summary S --tags a,b --body-file /tmp/X.md` |
| 双向关联 | `python -m hma.cli --root memory/<scope> link A B` |
| 单包重建索引 | `python -m hma.cli --root memory/<scope> rebuild` |
| 全仓重建 | 双击 `一键更新记忆索引.exe` 或 `python -m hma.engine --root memory rebuild-all` |
| 包级召回 | `python -m hma.engine --root memory query "<词>" --top-k 5` |
| 章级召回 | `python -m hma.engine --root memory query_anchors "<锚点>"` |

## 五、MCP 工具（11 个）

`memory_write` / `memory_query` / `memory_query_anchors` / `memory_read_section` / `memory_link` / `memory_ingest` / `memory_rebuild` / `memory_resolve` / `memory_aggregate`（计数问，unit ∈ packages/events/persons/locations/topics）/ `memory_time_filter`（模糊时间语硬过滤）/ `memory_obscure_recall`（不起眼物件细节追问）——由 `hma/server.py` 暴露，供 Agent 在对话中直接读写记忆。

> ⚠️ `memory_write` 若只传更新字段而**未带 body**，历史版本会清空既有正文（已加护栏拦截）。更新文档务必带上完整 body，或显式 `force_empty_body=True`。

## 六、排错

- **中文参数 not found**：cp936 下 MCP 入站参数曾因 stdin 按 locale 解码 UTF-8 字节而损坏 → 须重启/重载长驻 MCP 进程（server.py 已强制 UTF-8 IO）。
- **根 anchors 索引未建**：L2 报无匹配时，先用 exe 全仓 `rebuild_all`（单包 `rebuild` 不够，根级索引需全仓建）。
- **索引与 .md 不一致**：直接重跑 `一键更新记忆索引.exe`，`index.db` 可由 `.md` 全量重建，不丢数据。
