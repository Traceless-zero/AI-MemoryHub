# 领域检索后处理规范（法律 + 医疗）

> 适用范围：专业领域——法律（法条/案例检索）、医疗（鉴别诊断候选）。
> 本规范定义这两域共用的「召回后处理」约定：**全量 top 候选 + 无裁切**。
> FM 字段契约的权威见 `SCHEMA.md`；本规范只管「引擎返回结果之后怎么处理」。

## 0. 一句话结论

法律与医疗共用同一套后处理：引擎返回**全量加性分排序候选池**（不截断、不 dK 裁切），由**网页端把候选列表展示给人**；LLM 只做实体抽取、不做诊断/判断。这是《召回消歧管线设计（实现）》§防上下文爆量 中「通用叙事域 TOP1 接地」约定的**显式领域例外**——两域把「召回结果怎么被消费」交还给人与前端，而非 AI 接地层。

## 1. 为何需要领域例外（与通用域的根本分歧）

- **通用叙事域（Demo 类）**：回答需基于**单条最佳命中**接地，全量灌入会爆上下文、列清单式回复损害体验 → 约定 TOP1 接地、`top_k≤3`、超量即澄清。
- **专业域（法律/医疗）**：使用方是**人做鉴别判断**，必须看到**全部候选**（含近 misses / 兄弟条款）才能下结论 → 全量候选列表 + 无裁切。
- 二者不矛盾：**引擎检索机制完全相同，分歧只在「召回结果怎么被消费」**。专业域把消费权交给人和网页 UI，通用域把消费权交给 AI 接地层。

## 2. 引擎调用约定（query_anchors 参数集）

两域统一，调用方（编排层 / 网页后端）必须显式传：

- `rerank=False` —— 由 `if rerank:` 门控，`_rerank` 内部 `waterfall_cut`（dK 75 分差硬裁切）**不触发**。**严禁为这两域重开 rerank**（重开会重新引入裁切，破本规范；重开前须先改锚点级 BM25，见 `SCHEMA.md` 相关铁律）。
- `top_k = 全量` —— 所有 `score>0` 的包/锚点都返回，**不在引擎层截断到小池**（显式覆盖通用域 `top_k≤3` 的内部安全网）。
- `allow_abstain=False` —— 不触发 `theta=0.5` 相关性过滤、不触发实体硬拒答闸，弱候选不被丢弃；零匹配时池为空，UI 显示「无匹配候选」。
- 排序 = BM25+IDF 加性分降序（`scored.sort(key=(-score, pid, title))`）。`use_field_weights` 可选（仅加 bonu、只调序、非硬截断，与「仅凭加分」兼容；要严格纯核心分置 `False`）。
- **不走 `obscure_recall` 路径** —— 其内部带 `waterfall_cut`，会破坏「无裁切」。专业域用 `query_anchors` + `scope` 缩圈即可。

## 3. 两域共性：为何「无裁切」正确

- **医疗**：鉴别诊断须看全量候选（含近 misses），阶段N 补高判别力实体（BNP / NT-proBNP / 肌钙蛋白 / 射血分数 / 冠脉 CTA / 斑片状渗出 / 白细胞↑…）才收敛；dK 硬截断 / `top_k=5` 会埋掉待鉴别弱候选，提前丢失正解。
- **法律**：精确引证查询（「民法典32条」）gold 仍居首；全量池额外返回同包兄弟条款（33/34）作上下文，无副作用，反而利于「相关条款对照」。

## 4. 理解层职责（LLM = 纯抽取器）

- 专业域 LLM **只做实体/关键词抽取**（对应 `query_anchors` 的 `decomposer` / `keywords` 接口），**不做诊断、不推理、不生成结论、不锁单病、不加排序保护层**。
- 病人/用户 NL 描述 → 抽实体词 → 引擎零-ML 确定性检索 → 返回全量候选池。
- 反模式（禁止）：叠加 OR-fail-safe / rule#1 类「保 gold / 防挤出」保护层——dK 裁切自带保 gold 语义，多层冗余且冲突；LLM 侧也不做任何「只返回最佳一条」的硬选。

## 5. 前端职责（人做最终判断）

- 网页端把 top 候选列表（含分数/证据来源锚点）渲染给人（医生 / 律师 / 用户）看，由人做最终鉴别/判断/决策。
- 单实体 tie（如「气短」使心衰/冠心病并列）由「展示全量候选」自然化解——人看到并列即知要补查/补证，不逼 LLM 硬选单病。
- 医疗可叠加「分阶段渐进筛查」：阶段1 问诊粗筛返全量候选集 → 阶段N 探查报告实体叠加 `scope` 缩圈收敛（见 `MEMORY.md` 医学段「分阶段渐进筛查」）。

## 6. 与 CEMA 的对齐

AI = 理解层（抽取） / 引擎 = 确定性检索 / 人 = 最终判断。专业域把「判断」显式交还给人，LLM 不越权。

## 7. 反模式清单（禁止）

1. 为法律/医疗开 `rerank`（引入 `waterfall_cut` 裁切）。
2. `top_k=5`（或小池）截断候选。
3. `allow_abstain=True` 触发相关性/实体闸丢弱候选。
4. 走 `obscure_recall` 路径（带裁切）。
5. LLM 在引擎侧做诊断 / 排序保护 / 锁单病。

## 8. 边界对照表（与通用叙事域）

| 维度 | 通用叙事域（Demo 类） | 法律 + 医疗专业域 |
|---|---|---|
| 召回消费方 | AI 基于 TOP1 接地回复 | 网页端展示全量候选给人 |
| `top_k` | ≤ 3（内部安全网） | 全量（所有 score>0） |
| 裁切 | 允许（dK / top 小池，按场景） | **禁止** |
| LLM 角色 | 理解 + 接地 + 澄清 | **仅实体抽取** |
| 判断方 | AI 接地 + 超量澄清 | **人** |
| 典型接口 | `query_anchors(top_k≤3, allow_abstain=True)` | `query_anchors(rerank=False, top_k=全量, allow_abstain=False)` |

> 本规范是领域例外，不修改通用域约定；二者由调用方按域选择参数集区分。
