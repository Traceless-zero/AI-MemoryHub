# daylog.md 存入规范

> 配套实现：`hma/daylog.py`。本文件把「何时写 / 写什么 / 格式」固化成可操作的规范，
> 给 AI 与用户看；代码 docstring 是同一份事实的来源。

## 它是什么
`daylog` 是 **单日记录包**，属于 HMA 的「时间轴索引层」，与按主题组织的事件包**正交**：
主题事件包存「知识是什么」，daylog 存「哪天发生了什么」。两者靠 `linked` 互指，不重复存正文。

## 落点
```
memory/日志/daylog-YYYY-MM-DD.md
```
- 一天一包，`id` 内嵌日期（`daylog-2026-07-27`），日期即主键。
- 由 `python -m hma.engine 日志 add --text ...` 或 AI 调用 `hma.daylog.append_beat` 写入。

## 何时写（append_beat 的触发时机）
写，当且仅当出现以下任一种：
- 一个**进展 / 里程碑**完成（"搞定了 X""修掉了 Y 的 bug"）。
- **跨会话**时，想保留「今天时间线索」不丢失（夜间归档把话题溶进主题包后，时间线靠 daylog 兜底）。
- 一天结束时，回看「今天都干了啥」想留痕。

**不要写进 daylog 的**：
- 主题知识 / 结论本身 → 那应进**主题事件包**（活文档），daylog 只 `linked` 过去。
- 冗长正文 → daylog 是索引，不是仓库；权威叙事永远在主题包。

## 写什么（一段 beat = 一个进展）
- 一段叙事描述「这天发生的一件事」，像写日记，口语、连贯即可。
- 可用连接词让一天串起来：「先是 / 随后 / 接着 / 最后」。
- 长度：一段讲清一件事，不必长；一天可有多段（每段一次 `append_beat`）。
- 例：`修复了引擎 write 不派生 anchors 的坑，L2 章级检索现在能命中了`

## 格式（机器可解析）
每段叙事尾部跟一个侧车注释，包末引擎自动附索引 blockquote：
```markdown
# 2026-07-27 单日记录

修复了引擎 write 不派生 anchors 的坑，L2 章级检索现在能命中了
<!--beat linked:hma-core tags:引擎,anchors,L2-->

> 索引 · linked: [hma-core] · tags: [引擎, anchors, L2]
```
- `<!--beat linked:包id tags:关键词-->`：该段关联的**主题包 id** + **关键词**。
- `> 索引 ...`：包末汇总，引擎写回时自动生成，**不要手改**。

## linked / tags 填法
- **linked**：该段关联到的主题事件包 `id`（逗号分隔）。用于「精准搜寻命中 → 一对一映射回主题包正文」。
- **tags**：该段关键词（逗号分隔）。tags 同时被构造成 `anchors`，使单日包可被 `query_anchors` 发现（时间轴也能按词召回）。
- 没有关联就留空（仍是一段有效叙事）。

## 两种唤起
- **全天模糊型**「我那天都干了些什么」→ `日志 show <日期>`，列当天全部叙事。
- **精准搜寻型**「那天我是不是干了 XXX」→ `日志 show <日期> --q XXX`，在叙事段内做关键词匹配，命中后经 `linked` 调主题包正文。

## 纪律（无状态铁律 §13 合规）
- 单日包是**只读时间索引**；权威叙事在主题事件包。
- 时间只作 **WHERE 过滤键**（id 前缀字符串比较，确定性），结果按**日历序**排列，非热度/新鲜度权重。
