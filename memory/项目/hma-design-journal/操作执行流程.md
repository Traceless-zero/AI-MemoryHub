# AI记忆中枢（AI-MemoryHub / HMA）操作执行流程

> 本文档描述 HMA 各操作的**端到端执行流程**（从入口到落库/返回）。
> 配套架构说明见 `什么是HMA架构`；拆包与 front-matter 规约见 `信息架构与拆包策略`。
> 代码命名一律为 `hma`（`memory/` / `hma` 包 / `mcp__hma__*` 工具），对外产品名用「AI记忆中枢（AI-MemoryHub）」。

## 0. 系统分层与铁律（所有流程共享）

```
 用户 / AI 客户端
   │  （自然语言或 MCP 工具调用）
   ▼
 接口层   MCP server（stdio JSON-RPC）  ·  CLI（python -m hma.cli）
   │
   ▼
 引擎层   Memory 类（hma_core.py）：write / query / query_anchors /
   │        read_section / link / rebuild / rebuild_all
   │        run_ingest（主动收录管线，ingest.py）
   ▼
 存储层   memory/<namespace>/<id>.md   ← 唯一权威源（YAML front-matter + ## 正文）
          memory/index.db             ← 派生缓存（可随时全量重建，丢了不慌）
```

**贯穿所有操作的铁律**
1. **`.md` 唯一权威**：`index.db` 是派生缓存，可由所有 `.md` 的 front-matter 重建；绝不依赖 db 做真相。
2. **前后台 1:1**：每个事件包 = 一个 `.md`，对应索引恰好一条记录（复合主键 `(id, package_id)`）。
3. **确定性、无状态**：检索只做关键词/别名/Tag/锚点/时间过滤，**绝不加热度/新鲜度权重**。
4. **理解归 AI，落库/索引/关联归脚本**：AI 产出"包结构"，引擎做确定性 sink。
5. **三级检索漏斗**：L1 `query`（包/事件级关键词召回）→ L2 `query_anchors`（锚点级细粒度）→ L3 `read_section`（按需取正文）。前级缩窄范围，后级直取权威源，避免每次翻全库。

**作用域（package_id）**
- `Memory("memory")` → `package_id=""` → **全局**扫描。
- `Memory("memory/用户")` → `package_id="用户"` → 只扫该命名空间；且支持**嵌套/子孙检索**（`package_id="哲学"` 也命中 `哲学/尼采` 子树），放心嵌套目录。

## A. 写 / 改一个事件包（memory_write）

**入口**
- MCP 工具：`memory_write`
- CLI：`python -m hma.cli --root memory/<scope> write --id <id> --title ... --summary ... --tags ... --aliases ... --linked ... --body-file /tmp/x.md`
- 脚本：`Memory(root).write(id, title, summary, aliases, tags, linked, body, created, updated)`

**执行流程**
1. 组装 `EventPackage`（id / title / summary / aliases / tags / linked / body / anchors）。
2. **保留 created**：若 `id` 已存在，沿用原 `created`（不刷新创建日）；`updated` 取今天（或入参）。
3. **原子落盘**：写入 `<id>.md.tmp` → `os.replace` 成 `<id>.md`（崩溃安全，不会留半截文件）。
4. **确定性 upsert 索引**：`INSERT ... ON CONFLICT(id, package_id) DO UPDATE SET ...`——同 id 直接覆盖更新，真正幂等。
5. 返回落盘路径。

**边界**：`id` 存在 = 覆盖更新（不是新建）；`title`/`summary` 缺省时回退到 `id`；`anchors` 一般不手填（由派生流程写回）。

## B. 检索 L1 — 包/事件级关键词召回（memory_query）

**入口**：MCP `memory_query`；CLI `python -m hma.cli --root memory query "<q>"`

**执行流程**
1. 取作用域内全部事件行（`SELECT ... FROM events`，可按 `package_id` 限定或全局）。
2. 逐行 `_score`：`id` 命中(100) > `title`(60) > `alias`(50) > `tag`(40) > `summary`(20)；多词按空白切分累加；含 `trivial` 标签静态 −15（降噪，非热度）。
3. **确定性排序**：分数降序 → 更新日期降序 → id 升序（无随机、无权重）。
4. 截断 `top_k`（默认 5），返回 `[ (id, title, summary, score), ... ]`。

**边界**：只扫 front-matter 元数据，**不读正文**；`use_vector=` 参数已留但 ChromaDB 尚未接入，当前为纯确定性关键词；命中率低时降级到 L2。

---

## C. 检索 L2 — 锚点级细粒度召回（memory_query_anchors）

**入口**：MCP `memory_query_anchors`；CLI `python -m hma.cli --root memory query_anchors "<q>"`

**执行流程**
1. 取作用域内事件的 `anchors` JSON 字段（每个 `##` 派生出的子事件锚点）。
2. 逐锚点打分：标题精确(80) > 标题逐词(50) > 摘要词(30) > 标签精确(40) > 标签词(30)；多词全中 > 仅中一词。
3. 排序取 `top_k`，返回 `[ (pkg_id, anchor_title, anchor_summary, locator, score), ... ]`。
4. `locator` = 该锚点在正文里的 `##` 标题，可直接喂给 L3。

**用途**：长正文/故事包按"剧情节点/小节"召回——L1 用包级词可能漏，L2 能命中锚点里的特征词（如「纽约之战」「圣保罗之焰」）。

---

## D. 读正文 L3 — 按需取某一段（memory_read_section）

**入口**：MCP `memory_read_section`；CLI `python -m hma.cli --root memory read_section <id> "<heading>"`

**执行流程**
1. `read(id)`：先按索引 `filepath` 定位 `.md`，文件缺失则回退到 `events_dir/<id>.md` 直读；读入并回填来源路径。
2. 把 `body` 按行扫描，找首个 `##`/`###` 小标题**包含** `heading` 的行作为起点。
3. 向下收集，直到遇到同级或更高级别的小标题为止 → 截出该段。
4. 返回该段 markdown；找不到返回 `(section not found)`。

**用途**：配合 L2 的 `locator` 使用——先 `query_anchors` 拿 locator，再 `read_section` 精准取正文，**省上下文窗口**（不把整包正文塞进 prompt）。

---

## E. 关联两个事件包（memory_link）

**入口**：MCP `memory_link`；CLI `python -m hma.cli --root memory link <a> <b>`；脚本 `Memory.link(a, b)`

**执行流程**
1. `read` 两端点；任一不存在 → 抛 `事件包不存在` 错误。
2. 互相把对方 append 进各自的 `linked` 列表（去重）。
3. **各写回各自原始目录**（`_write_back` 按 `pkg.path` 定位，跨包 link 不再把文件"搬家"到根目录，避免产生 `package_id=''` 重复包体）。
4. 返回 `linked: a <-> b`。

**边界**：关联是双向、且只改 front-matter 的 `linked` 字段（索引视图随之更新），不动正文。

---

## F. 主动收录（memory_ingest / hma-ingest 技能）

**入口**：MCP `memory_ingest`；CLI `python -m hma.cli --root memory ingest "<文本>"`；技能 `hma-ingest`（含模块路由 / 拆包铁律）

**执行流程（run_ingest）**
1. `list_summaries()`：取现有事件包的 `(id, title, summary)`（**只摘要，不扫正文**）——用于关联发现。
2. **若有 LLM 适配器**（设了 `HMA_LLM` + API key）：用 `build_prompt` 构造提示词 → 调模型 → `parse_plan` 解析出 `packages[]` + `links[]`（JSON：id/title/summary/tags/aliases/body）。
3. **若无适配器**（零成本路线）：退化为单包启发式——取首行作 title，整段作 body，tags 含 `scope`，id 用 `slugify(首行)` 或 `note-<md5>`。
4. 逐个包：`slugify(id)` 保 kebab-case 唯一 → `Memory.write(...)` 落库（逐一 upsert 索引）。
5. **自动关联**：对 `links[]` 中"两端 id 都在（新创建 ∪ 已存在）集合里"的配对，调用 `Memory.link`（防编造不存在的 id）。
6. 返回人类可读摘要：`ingested N package(s): ...` + `linked M: ...`。

**技能层（hma-ingest）额外做的**：模块路由（用户/项目按 5 模块 / README 式拆包增补，不新建单体）、一次比对 index 同时完成"归并候选 + 关联发现"、落库后追加 daylog 叙事、输出「收录钩子」让用户可纠错（合并/移包）。

---

## G. 索引重建（memory_rebuild / rebuild_all / 一键 EXE）

**入口**
- MCP `memory_rebuild` → `Memory.rebuild()`（**只重建当前作用域**）
- 全量权威命令：`python scripts/rebuild_index.py --no-gui`（= `rebuild_all` + 锚点派生 + 重生成目录树）
- 双击 `一键更新记忆索引.exe`（同一条路径，零 AI）

**执行流程（rebuild_all，脚本走这条）**
1. `DELETE FROM events`（清全库索引）。
2. 遍历 `memory/` 下所有命名空间/包/事件 `.md`：解析 front-matter → upsert 索引。
3. **派生 anchors**：扫每个 `.md` 的 `##` 标题树 → 算 `anchors` → 写回 front-matter（引擎托管字段，符合"anchors 不手填"规约）。
4. 重生成 `memory/目录结构树.md`（派生缓存，Orientation 用）。
5. 返回重建事件包数。

**边界**：`rebuild()` 只 `DELETE ... WHERE package_id=?`（只动当前包，安全装卸单文件夹）；`rebuild_all` 才清全库。`.md` 是权威，重建永不丢数据。

---

## H. 锚点派生（derive）

**入口**：`python -m hma.engine derive <已落库目录>`

**执行流程**
1. 目标须为**已落库目录**（直接含事件 `.md`）。
2. 扫每个 `.md` 正文的 `##` 标题树 → 算 `anchors` 列表（title/summary/locator/tags）。
3. **合并语义**：派生打底 + 保留用户手写修改——正文新 `##` 补派生、已手改的留用户版、被删的 `##` 删锚点、用户锚定子节(`###`)保留。
4. 幂等：合并结果与现存一致则跳过写，不产生 changes 噪声；加 `--force` 则整组覆盖为纯派生版。

**边界**：派生是重建流程（G）的内置一步；一般不必单独跑，改完包后跑 `rebuild_index.py` 即可。

## I. 日志（daylog 叙事型记录）

**入口**：`python -m hma.engine 日志 add "<叙事>" --linked "<id,id>" --tags "<k1,k2>"`

**执行流程**
1. 单日包 id = `daylog-YYYY-MM-DD`，默认落 `memory/日志/`。
2. `add`：向当天包**追加一段叙事**（日记式，非关键词卡片），并记 `--linked`/`--tags` 索引侧车。
3. 一次收录 = 一段叙事，不把多次合并成一段。

**召回**：`日志 show <YYYY-MM-DD>`（全天）/ `日志 show <d> --q "<词>"`（精准）/ `日志 range --start <d1> --end <d2>`（一段日子）。需要细节时沿 `linked` 用 L2/L3 取主题包正文。

**边界**：daylog 只装"闲话 + 大事件简介 + 关联"，结构化项目跟踪进 `项目/<x>/` 对应包，daylog 不承载真相。

---

## J. MCP 调度（JSON-RPC 路由）

**入口**：`python -m hma.server --root memory`（stdio，纯标准库，零第三方依赖）

**执行流程（dispatch）**
1. stdin 逐行读 newline-delimited JSON-RPC 2.0 请求（stdout 只发协议消息，日志走 stderr）。
2. `initialize` → 回协议版本 + serverInfo（`hma` / `0.1.0`）。
3. `tools/list` → 回 7 个工具定义（write/query/query_anchors/read_section/link/rebuild/ingest）。
4. `tools/call` → 按 `name` 查 `HANDLERS` 表 → 调对应 `_h_*`：
   - `_store(root)` 按 root 缓存单例 `Memory`（避免每调用新建连接泄漏文件锁）。
   - 工具内部异常 → 返回 `isError:true` 的文本，**不断开连接**。
5. 未知 method/tool → `-32601` 错误。

**边界**：server 是单进程单线程长驻；`--root` 默认 `os.environ.get("HMA_ROOT","memory")`；部署用 `scripts/deploy_mcp.py` 落地到 `~/.workbuddy/` 并自定位 `memory/`（零写死路径）。

## 串联示例：收录 → 检索 → 读正文 闭环

```
① 用户：「把这段存进记忆」（hma-ingest 技能）
   → F 收录：AI 拆包 → Memory.write 落 memory/用户/<id>.md + upsert 索引
   → 追加 daylog 叙事（I）

② 用户：「半年前那个 HMA 项目是啥」
   → B(L1) query "HMA 项目" → 命中 memory/项目/hma-design-journal 的 summary（冷答，不读正文）

③ 用户：「展开讲那个设计决策」
   → C(L2) query_anchors "真相模型" → 命中锚点，拿到 locator="真相模型（R46 拍板）"
   → D(L3) read_section <id> "真相模型（R46 拍板）" → 精准返回该段正文

④ 关联：memory_link <a> <b> → 两端 front-matter linked 互写（E）
⑤ 索引维护：跑 scripts/rebuild_index.py 全量重建 + 派生 anchors（G+H）
```

## 边界与未接入项（如实标注）

- **向量检索未接入**：`query(use_vector=)` 参数已留，但 ChromaDB 层未实现；当前检索为确定性关键词，对"主题模糊"类需求靠 AI 反问逼清晰，不引入幻觉。
- **付费 LLM 路径未激活**：`note` 模式 + `llm_adapter` 已留 env-gated 接口（`HMA_LLM` + key），未配 key 时全走零成本 Agent 路线（F 的启发式兜底）。
- **落库直写 `memory/`**：敏感内容留在仓库外，库内只记指向（如「详见 ~/private/xxx.md」）。
- **MCP 连接器待用户在 WB 连接器页点「信任」激活**：激活后本会话才见 `mcp__hma__*` 工具。
