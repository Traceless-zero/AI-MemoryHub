# HMA 用户操作手册（手把手）

> 这份手册是 HMA 给你的「新手向导」。你不用记命令、不用看代码——
> 下面的每一步都给你"说什么、会发生什么"的真实例子。跟着做一遍就会了。

## 一分钟认识 HMA

**HMA = Hybrid Memory Architecture**，一句话：给 AI 装一套**长期记忆外骨骼**。

普通 AI 每次对话都像"新生"——不记得你是谁、昨天答应过什么、项目做到哪了（俗称"金鱼脑"）。HMA 让 AI 跨对话**记得住、理得清、长经验**。

几个关键点：
- **不绑定任何大模型**：零运行时依赖（纯 Python 标准库），换模型不影响记忆。
- **记忆最小单元 = 事件包**：一个 `.md` 文件（索引头 + 正文）。所有记忆都是"事件"，没有模糊的"短期/长期"之分。
- **五个内容命名空间**：`用户/`（你的偏好）、`项目/`（项目包，含本手册所在的 `hma-design-journal`）、`原创角色/`（OC 角色）、`日志/`（每日记录）、`其他/`（文章资料）。主题边界是**结构性的**，不会混。
- **AI 只理解，脚本确定性写**：归类、拆分、关联判断归 AI；落库、建索引、重建交给脚本——稳定、可复现、不吃运气。

## 怎么打开 HMA（启动 vs 常驻）

两种方式，效果一样：

**① 手动开（总开关）**
对话里说一句：
> 「启动HMA架构」／「开启HMA记忆」／「切到记忆存储模式」

AI 回你一句确认，本对话剩余轮次就处于**记忆模式**：你说"记一下"就存，说"回忆X"就查。

**② 常驻（不用喊）**
项目自带 `hma-always` 技能：会话一开始 AI 就**默认带记忆意识**，浮现值得记的东西会主动存、问题依赖过往上下文会主动查。你甚至可以完全不提"HMA"三个字。

**关闭**
> 「关闭 HMA 记忆模式」

记忆模式退出，恢复正常助手；**已落库的记忆一个都不删**。

## 怎么存东西：让 AI 帮你记

你不用学任何命令。两条路：

**A. 你说"记"**
> 你：「记一下，我偏好用中文注释、不用英文缩写。」
> AI：（理解=用户偏好，落库进 `用户/` 包）已记下 ✅

**B. AI 主动存（常驻模式）**
多轮对话里冒出非显然结论、踩坑、决策时，AI 会自己判断"这值得记"并收录——不用你每次喊。

**想存一大段**（文章 / 笔记 / 长想法）：
> 你：（贴一段文字）「把这收进记忆。」
> AI：（理解拆分 → 写入对应包 + 建索引）

底层原则不变：**AI 只做理解，落库建索引全交脚本**，确定性、可重建。

## 怎么查东西：三级检索漏斗 L1→L2→L3

记了之后怎么调出来？说：
> 「回忆一下我们说的 HMA 检索」「查一下那个 OC 角色」「之前聊的 X 是什么」

HMA 用**三级漏斗**逐级由粗到细，确定性、不按热度排序：

- **L1 包级**：在索引里找"对哪个包"命中（极快，只看元数据）。
- **L2 章级锚点**：包很大时，定位到"哪一节"命中。
- **L3 取正文**：确定章节后，才读那段 `.md` 原文（省上下文）。

好奇底层长什么样（可选看）：
```bash
python -m hma.engine query       <root> "HMA检索"        # L1 包级
python -m hma.engine query_anchors <root> "锚点关键词"     # L2 章级
python -m hma.engine read_section  <root> <id> "<章节>"    # L3 取正文
```
日常你只管说话，AI 帮你跑这些。

## 怎么存一个原创角色（OC）

写小说 / 跑团 / 人设练习，想把角色长期记住？

> 你：（丢来一段人物文字或文件）「把这个角色存下来。」

AI 走 `oc-dossier`（store 分支）：先判定这段文字是"结构化档案"还是"散碎描述"，再按 **CEMA 三层铁律**自动拆包：
- **基础包**（必有且唯一）：姓名 + 形象 + 语气
- **故事包**（背景长就分立）：经历 / 剧情线
- **拓展包**（有就分、无则无）：关系网 / 彩蛋

存好之后，对话里**直接叫角色名字**，AI 唤醒它陪你聊（`oc-dossier`（wake 分支））——相当于给 AI 加载了一个"可插拔身份"。

## 怎么把别的 AI 客户端的记忆搬进来

你如果在 WorkBuddy / Claude Code / Gemini / Codex 里已经攒了原生记忆，不用重来：

> 你：「把 Claude 的记忆收进 HMA」／「导入我的 WB 工作日志」

`memory-import` 按当前路径**自动探测**是哪个客户端，跑对应迁移脚本，给你的旧记忆装上 HMA 的**可检索索引**（可链接、按需取正文）。原记忆文件不抄第二份，只加索引。

## 隐私与边界：有些包不能碰

- **私有包保护**：像 `private` 这类你标记为私有的包，AI 绝不外泄、也绝不误写——命名空间层面兜底。
- **关闭不删数据**：退出记忆模式只是停"主动路由"，已存记忆原样保留。
- **本地纯文件**：记忆库就是 `memory/` 下一堆 `.md`，控制权完全在你，随时可备份 / 手改。

## 索引丢了 / 手改了 .md 怎么办

`index.db` 只是**派生缓存**，真正的权威源是 `.md`。所以：
- 手改了 `memory/` 下某个 `.md`；
- 或索引看着不对 / 想强制刷新；

→ **双击** `hma/一键更新记忆索引.exe`（零依赖、弹窗回报），或命令行：
```bash
python scripts/rebuild_index.py          # 全量重建 index.db + 目录树，零 AI
```
幂等、随时可跑、不丢数据——这就是 HMA 的"可重建信仰"。

## 常见问题（FAQ）

**Q：常驻模式会不会偷偷吃很多 token？**
A：检索只在元数据层发生，粗答（只回摘要）极廉价；只有你要展开才读正文。HMA 是为"可检索 / 可链接 / 可审计 / 长期不腐"设计的，**不是为省 token**——这是刻意取舍，低频轻量记忆上它显得重，但换来了不腐的记忆。

**Q：能和别人共用一份记忆吗？**
A：记忆库是本地目录，按目录隔离。多人各用各的 `memory/`，或复制目录分发。

**Q：记忆会丢吗？**
A：不会。`.md` 是唯一权威源，`index.db` 可全量重建；即使删了索引文件，重跑重建脚本就能恢复，正文不丢。

**Q：一定要开新窗口 MCP 才生效？**
A：MCP 工具（接进客户端后）在**会话启动时**注入，所以新会话才看得到 `mcp__hma__*` 工具。但**常驻 `hma-always` 不依赖 MCP**——它走引擎 CLI 也能主动存 / 取，当前窗口就能用。
