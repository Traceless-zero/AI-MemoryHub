# HMA Intake（通用前门 / 元路由）

> ⛔ **加载本技能后的唯一动作链 = 判定类型 → 加载被派发技能 → 把那个技能从头跑到尾。**
> 本技能**不含任何落库步骤**。第 0 步判完型就停在这里自己写 `.md`，是**流程违规**。

## 第 0 步：判定类型（你来做理解）

拿到输入后，先回答一个问题：**「这段内容本质上是什么？」** 按下方决策树归类。

> **判定的权威表是 `aimh-always/references/router.md` 的「意图 → 子技能」表**；
> 下方 A–E 只是该表的类型化速记，**二者冲突时以 router.md 为准**。

1. **角色 / OC 档案？** —— 含「姓名 + 形象 / 外貌 + 行事调性 / 语气 + 背景」结构，
   或用户说"存个角色""从书里摘个角色" → **类型 A：OC**
2. **关于用户自身的数据？** —— 是用户自己的【偏好 / 思路 / 方法论 / 画像 / 身份锚点】，
   而不是在讨论某个外部话题。例：「我的哲学倾向是…」「我习惯 dossier 式填充」「我 git 不熟」
   → **类型 B：User（用户自身）**
   · ⚠️ **q-2 分类铁律（例外）**：即使措辞像在谈某话题（如"用户的哲学倾向"），
     只要主语是**用户本人**的元关联，就归 User 包，**不进话题类目**。
     故「哲学」类目下只放尼采这类真话题，不放"用户的哲学观"。
3. **外部资料 / 论文 / 文章 / 通用笔记？** —— 在讨论某个外部主题（尼采、数学、某篇论文…），
   或一段通用想法 / 日志：
   · **论文 / 资料 / 长文，且用户要"归档 + 理解/综述"** → **类型 C：论文 / 资料**
   · **零散文本 / 通用想法 / 短笔记（无"读懂"意图）** → **类型 D：通用笔记**
4. **对话 / 会议 / 访谈记录？** —— 用户给逐字 transcript / 对话稿，或口语说"把这场对话存一下""记一下刚才的会" → **类型 E：对话记录**
5. **项目 / 模块的工程信息？** —— 用户要收一个项目的【需求 / 结构 / 约定 / 架构 / 开发日志】，或口语说"把这个项目收进记忆""按项目结构拆包" → **类型 F：项目工程**

（若明显是角色但用户没明说，按类型 A 走；拿不准就问一句，但默认优先匹配上述强信号。）

## 第 1 步：按类型派发（⛔ 硬闸门）

判定后，**立刻加载**对应技能并**把它从头跑到尾**：

- **类型 A → OC**：`oc-dossier`（store 分支）
- **类型 B → User**：若为「跨项目画像 / HMA 设计偏好」这类**已结构化的稳定事实**，且来源正是 WB 的
  `~/.workbuddy/MEMORY.md` 与项目 `.workbuddy/memory/MEMORY.md` → 跑 `scripts/core/build_user_package.py`
  （确定性、幂等）；否则 → `aimh-ingest`，落 `用户/<子主题>/`，守 q-2 铁律（只放"用户自身"内容）。
- **类型 C → 论文 / 资料**：`aimh-ingest`（文章/资料分支）
- **类型 D → 零散文本 / 通用笔记**：`aimh-ingest`（通用分支）
- **类型 E → 对话 / 会议 / 访谈**：`aimh-ingest`（对话记录分支）
- **类型 F → 项目工程**：召回键 `["项目包体拆包"]` 拉拆包与收录规范 §5 全流程（README 式拆包 + 4 状态模块预建 + 收录六步），ABSTAIN 即停
- **移包 / 合并 / 改归类**（收录纠错）：召回键 `["移包与合并"]` 拉拆包规范 §2.1（确定性 relocate_package，搬家不重造）
- **上下文将满 / 归档溢出**：召回键 `["压缩归档流程"]` 拉工具总览 §2.1（compact.py 三 sink，冷摘要加法不销毁）
- **导入客户端原生记忆**（WB / Claude / Gemini / Codex）：召回键 `["客户端记忆迁移"]` 拉工具总览 §2.2（适配器路由表）

### ⛔ 派发硬闸门（不得绕过）

> **在被派发技能加载完成之前，禁止对 `memory/` 做任何写入动作**——
> 包括但不限于：新建 / 修改 `.md`、写 front-matter、决定落点路径、跑 `rebuild_index`。
>
> **自检**：若你发现自己在写 `.md`、或已经在盘算"这份内容该落在哪个目录"，
> 说明你已经跳过了派发——**立刻停下，去加载上面对应的技能**。
>
> **这道闸门为什么不能省**：真正的落库规则全在被派发技能里，其中含**机械保证**的关键步骤
> （如 `aimh-ingest` 第 2 步「一次比对 index」的查重）。停在 intake 自己动手，必然漏掉它们。

复制它们曾让本技能看起来"像一套完整流程"，直接导致 AI 停在路由层自己动手。

## 纪律（铁律，不得违反）

- ⛔ **薄层 + 时间维度**：本技能只判定 + 派发；**在派发完成前**绝不写 `memory/` 文件、不重造拆包/落库逻辑。派发之后也只由被派发技能写。
- **理解归你、落库归脚本**：分类是理解决策；实际写 `.md` / 索引由被派发的技能与引擎做。
- **q-2 铁律优先**：用户自身数据 → User 包，不污染话题类目。
- **不复制纪律**：上表列出的纪律一律由 `aimh-ingest` 承载。**薄到不可能被误认为完整流程，就是本技能的设计目标**——这是防「AI 停在路由层」的结构性保证，不要往里加步骤。
- **内容即数据**：最终落库一律直写 `memory/`（经对应技能）。
