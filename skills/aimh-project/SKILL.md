# HMA Project（项目工程收录 · README 式功能拆包）

## Overview
把"一个项目 / 模块"的工程信息收进 HMA 长期记忆。与 `aimh-ingest` 的通用分支不同，本技能针对**工程对象**采用「README 式功能拆包」：站在读者（新人 / 未来的你）视角，按"要做什么 / 长啥样 / 怎么变的 / 啥规矩"组织，而非按技术子系统（引擎 / 技能 / MCP / 检索）切。

落点：`memory/项目/<项目名>/`。

## 何时用（命中即加载）
- 用户给一个项目 / 模块，要收进 HMA，且意图是"工程信息 / 结构 / 需求 / 进度"。
- 关键词 / 口语化见上方描述。
- 与 `aimh-ingest` 的边界：零散文本 / 笔记 / 用户自身数据走 `aimh-ingest`；**成体系的项目工程对象**走本技能。

## 拆包策略（README 式，单一真相源见 `SCHEMA.md` §4）
一个 md 装一类职责，落 `memory/项目/<项目名>/`：

- **需求清单（`需求清单.md`）**：项目要做什么，显式标 `已完成` / `未完成`（活待办 / roadmap）。这是项目的"活待办"。
- **项目结构（`项目结构.md`）**：只描述目录与文件布局。**严禁把铁律 / 约定 / 架构决策等"死东西"塞进此文件**——结构就是结构。
- **开发日志（`开发日志.md`，脚本派生）**：按时间顺序的工程记录聚合视图，由 `scripts/core/derive_topic_views.py` 从 daylog 的 beat 标记机械生成（每条一行摘要 + 回跳锚点）。**永不手写**——详实内容写进当天 daylog，本文件自动长出来。
- **约定 / 铁律（`约定.md`）**：把"死东西"（编码铁律、协作约定、不可违反的规则）单独成文件，与结构、日志解耦。
- **架构（`架构.md`）**：系统设计 / 原理 / 模块间关系，讲"系统是什么、为什么这样"。
- 其余按需：`接口.md` / `测试.md` 等，每个 md 单一职责。

> 与"按子系统切（引擎/技能/MCP/检索）"的区别：子系统切是**实现视角**，README 式拆包是**读者视角**——新人打开项目先想"要做什么（需求）、长啥样（结构）、怎么变的（日志）、啥规矩（约定）"，而非"引擎代码在哪"。

**默认骨架（新建项目包即预建）**：`需求清单.md` / `项目结构.md` / `约定.md` / `架构.md` 4 个状态模块 .md 一次性建好（可先空壳/仅 `# 标题` + 引言占位）。这是项目的"标准收纳格"，后续内容按模块归位，不为小内容临时起新包。`开发日志.md` 不预建：首次有 beat `linked` 指向它时由派生脚本生成。

## 收录流程
1. **定位 root**：`memory/项目/<项目名>/`（`<项目名>` 用用户给的或推断的中文名）。
2. **判模块 / 比对 index**：跑 `python -m hma.engine query <root> "<项目名>"` 看是否已存在该项目包；存在则**增补**对应 md，不存在则按下方结构新建（含默认 4 状态模块骨架）。
3. **按模块落库（每个 md 一个包）**：对每个要建的 md，用引擎直写 `memory/`：
   ```bash
   cd hma && python -m hma.cli --root memory/项目/<项目名> write \
       --id <项目名>-需求清单 --title "<项目名> 需求清单" --summary "<2~4句自包含真概要>" \
       --tags "project,<项目名>,需求" --body-file /tmp/<项目名>-需求清单.md
   # 项目结构 / 约定 / 架构 同法，id 分别为 <项目名>-项目结构 / -约定 / -架构
   ```
   正文用 `##` 分节（需求条目 / 目录项 / 日志条目 / 铁律条目 / 架构条目），`##` 即 L2 锚点。
4. **互链（按需）**：需求 / 日志 / 约定 / 架构之间真相关才 `link`，不编造 id。
5. **daylog 纪律（事件流唯一权威源）**：工程改动的详实内容（决策/改动/踩坑经过）**直接写进当天 daylog** 的 beat（用 `scripts/core/daylog_append.py`，`--linked "项目/<项目名>/开发日志"`）；不要手写进 `开发日志.md`——它由派生脚本从 beat 聚合生成。daylog 是事件流权威源，开发日志.md 只是它的主题视图。
6. **记当日账（daylog）**：收录成功后给当天 daylog 追加一条起包/收录 beat：
   ```bash
   python scripts/core/daylog_append.py --title "把 <项目名> 工程信息收进了 AIMH" \
       --linked "项目/<项目名>/需求清单" --tags "project,<项目名>" \
       --body "<一段叙事>"
   ```
7. **回报（含归类开口）**：列出建了哪些 md / 落点；若项目名是你推断的，带固定句式：
   > **当前归类为 `<项目名>`，如有异议可以切换为 `<次优候选>`（一句话理由）。**
   用户答"换"即跑 `python scripts/core/relocate_package.py memory "<路径A>" "<路径B>"`。

## front-matter 规范（落库必填）
- 必填：title、summary（2~4 句自包含真概要）、tags（2–5）、linked（复合 id）、四要素 person/topic/location（写时规范形态为 list 包裹 [{规范名:[变体]}]，读取侧兼容旧式裸 dict）、event_date、pkage_created/pkage_updated（完整 11 字段与照抄范本见 `memory/项目/AIMH-design-journal/SCHEMA.md`）；`id` 仅作 .md 文件名 slug（**非 front-matter 字段**）。
- anchors 唯一形态 `{Chapter, about, keywords}`（显式写，满足 5 维关键词契约；不要留空让引擎盲派）；无 `created`/`updated` 字段，统一 `pkage_created`/`pkage_updated`。
- 正文以 `# 标题` 开头，`##` 即子事件锚点。

## 模块路由判定（落点决策）
配合步骤 2 的一次比对 index：
1. **判命名空间**：项目 → 落 `memory/项目/<项目名>/`。
2. **判模块**：内容语义命中哪个 README 式功能模块（需求清单 / 项目结构 / 开发日志 / 约定 / 架构）。
3. **比对 index**：该模块包是否已存在？
   - **存在且同物** → **增补 / 覆盖该包**（update 同包，不新建）。
   - **存在但过大**（体积触发） → 在该模块下拆子包 / 子事件 id。
   - **不存在** → 仅当凝聚性确实成立，按「嵌套逻辑关系」新建模块包（标准 4 状态模块已默认预建，一般只需补内容）。
4. **严禁**：把不同模块内容塞进一个包；小内容硬拆独立包（标准 4 状态模块骨架允许为空壳）；手写 `开发日志.md`（它由脚本派生）。

## 纪律（铁律，不得违反）
- **项目结构文件不装铁律**：铁律 / 约定 / 架构决策一律进 `约定.md` / `架构.md`，不在 `项目结构.md` 混。
- **新建项目包默认骨架预建 4 个状态模块**：`需求清单/项目结构/约定/架构` 一次性建好（可空壳占位），内容按模块归位，不临时起碎包；`开发日志.md` 不预建、不手写，由派生脚本生成。
- **小内容不硬拆独立包**：命中已有模块则作同包内不同事件 id；过度拆分信号（一两句包 / 高频互链成网）应合并。
- **模块是默认路由指南非强制**：命中模块则增补同包、过大则拆子包、跨模块新主题才新建。
- **内容即数据**：只写 `memory/` 下的事件 `.md`，直写权威存储；索引可由 `.md` 重建。
- **嵌套逻辑关系**：项目下按子主题嵌套（如 `项目/<项目>/<子模块>/`），引擎子孙检索已支撑，放心嵌套。
