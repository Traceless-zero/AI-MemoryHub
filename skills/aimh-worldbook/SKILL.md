# AIMH 世界书拆解器（Worldbook Decomposer）

## Overview
作家写书前先有**世界书**（人物、关系、时间线、地理、概念演变、故事线），再把世界书投影成线性章节。
读者看到章节，但所有章节的锚点都连着那本世界书。AIMH 做「实体聚合提取」，在工程上就是
**从一本完整书/长文反推出一套世界书的逆向构建**——人物包=人物卡，topic=概念/主题卡，
anchors=章节到世界书的索引指针，linked=世界书内部的互引网络。

本技能把这套「反推世界书」的流程沉淀为可复用骨架。**它不是 AI 自由发挥写包**，而是严格遵守 CEMA：
- **AI 理解层**：读长文，抽实体（人物/地点/时间线/概念/故事线），产出实体清单与关键属性；
- **脚本确定性落盘**：按 FM-V2 契约把实体落成 AIMH 包（概览 + 分章 + 聚合视图），自动建 linked、anchors 五维、topic 描述表达式；
- **路由规则**：内置「何时建聚合包」的决策（见下）。

> **为什么需要它**：AIMH 用结构化换精准命中，但「超级问题」（跨包聚合问，如"示例人物经历了什么"）
> 依赖预先建好的聚合视图。手工建世界书慢且易漏；本技能把今晚手工跑的战争与和平样例
> （概览包 + 6 分章包 + 示例人物人物线包）抽象成可复用流程。

## 触发与回问（核心交互）
本技能是**可选**的。AI 在会话中处理文本时，按以下逻辑决定是否提议：

1. **监测 token 消耗**：当待处理文本字数超过阈值（默认 **建议值 30000 字**，即约一本中篇/大长篇切片门槛；
   世界书拆解对象本就是「书/长篇资料」，几万字起步才合理，可由用户/会话按书调整），
   或 AI 判断「整篇塞进上下文不经济」时，进入触发态。
2. **回问用户（不擅自执行）**：用一句话回问，例如：
   > 「这篇文本较长（约 X 字），直接通读会占用大量上下文。是否需要我用「世界书拆解器」
   > 把它拆成结构化的世界书（人物卡/概念卡/章节索引），之后你按需调取片段即可？」
3. **用户确认后才执行**；用户拒绝则退回普通读取/aimh-ingest 短包路径。
4. **绝不静默拆解**——长文拆解会落多个包、改记忆库结构，必须显式确认（符合删除/改动红线精神）。

## 世界书固定结构（拆解产物 schema）
拆解后落盘的包集合（均遵循 FM-V2，详见 `memory/项目/AIMH-design-journal/SCHEMA.md`）：

| 包类型 | 命名（中文） | 内容 | 关键字段 |
|---|---|---|---|
| 概览包 | `<书名>·全书概要` | 全书篇幅/主线/核心人物一句话 | person/topic/anchors/summary 全填实 |
| 分章包 | `<书名>·第X卷第Y部` 或 `<书名>·第X章` | 该章正文大段散文 + 本章实体 | person/topic/location/event_date/anchors |
| 人物聚合包 | `<书名>·<人物名>人物线` | 该人物贯穿全书的命运线（**引用 linked 各章，不抄内容**） | person 含精确别名；topic 含"人物经历/人物线"；linked 指向分章包 |
| 概念/主题聚合包 | `<书名>·<概念名>概念线` | 该概念跨章演变（可选，长尾按需） | topic 含概念描述表达式；linked 指向相关分章 |

**聚合包铁律**（用户 2026-08-22 拍板）：
- 聚合包是**索引视图，不是重复存储**——正文用 linked 指向各分章包，不抄内容；
- 单人视角作品（如示例角色第一人称）**不建**人物聚合包（本职即单人视角，无需跨卷索引）；
- 跨多章出现的核心实体才建聚合包；只在一章出现的次要实体不建。

**适用边界铁律**（用户 2026-08-22 拍板）：
- 「世界书」本质是**多视角/多实体作品**才有的东西——世界里有多个独立人物、地点、并行故事线，才需要从成书反推网状结构（人物卡/关系网/时间线交错）。
- **单人视角小说主线聚焦、实体单一**，反推出的"世界书"退化成"主角一人经历时间线"，不是 world bible，是 character diary。**本技能对单人视角作品整体不适用**——保持单包 + 全字段即可，不拆多包、不建聚合包。
- 若单人视角作品通读 token 过大，靠**读取侧按需取 anchors 片段**解决，不靠拆包。

## 执行流程（CEMA 合规）
1. **AI 抽实体**：读长文，产出实体清单——人物（含别名/关系）、地点、时间线节点、核心概念、故事线分段。
   这一步 AI 只理解，不落盘。
2. **规划包结构**：按上面 schema 决定建哪些包（概览/分章粒度/哪些聚合包）。粒度规则：
   分章包按原文自然分卷/分章；聚合包只对「跨多章核心实体」建。
3. **脚本确定性落盘**：逐包写 FM-V2 front-matter + 正文。**推荐直写 `.md`**（按 SCHEMA §2.8 范本落文件）或 `Memory(root).write(...)`。
   ⚠️ `python -m hma.cli ... write` 的旗标**无法携带四要素 dict / `pkage_created`/`pkage_updated`，会丢字段**，仅适合极简包——世界书各包 person/topic/location 全填实，**不要走 CLI**。
   linked 用相对 memory 根的路径。写完按第 4 步重建索引。
4. **建索引**：跑 `rebuild_index`（或「一键更新记忆索引」）重建锚点索引，确保新包可被检索。
5. **lint 验收**（仓库根下执行）：跑 `python scripts/core/lint_memory.py --all` 确认所有新包契约合规（引号格式、五维 keywords、11 字段齐备等）。
   > 旧写法「跑 `aimh-fm-update` 的 lint」已失效——`aimh-fm-update` 技能及其依赖的 `fix_frontmatter.py` **已于 2026-08-28 移除**（脚本全仓不存在、技能为死技能）。lint 能力本身未丢，直接调上面的脚本即可。

## 与现有体系的关系
- **aimh-ingest**：短文本/通用归档的默认前门；本技能是长文本的「世界书」增强分支，不替代它。
- **oc-dossier**：单个 OC 角色档案；本技能是整书多包世界书，含 oc-dossier 不覆盖的概览/分章/概念卡。
- **derive_topic_views.py**：daylog → topic views 的机械派生；本技能是「长文 → 世界书」的同构逆操作。
