# HMA Intake（通用前门 / 元路由）

## Overview
用户给一段文本 / 一个文件，说"存进记忆 / 归档 / 整理一下"。但内容可能是 OC 角色、
可能是论文、可能是用户自己的偏好笔记——落库流程完全不同。本技能让**当前会话的
Agent（你）先判定类型**，再**加载对应的专用技能**去执行，不重复造轮子。

> 设计哲学（对齐 HMA 初心「即插即用的记忆存储外挂」）：skill = 可插拔客户端，
> 前门只负责把对的请求送进对的 skill。OC 专用流程（oc-dossier）保持独立不变，
> 本技能只是它的一个【调用入口】。

## 第 0 步：判定类型（你来做理解）
拿到输入后，先回答一个问题：**「这段内容本质上是什么？」** 按下方决策树归类：

1. **角色 / OC 档案？** —— 含「姓名 + 形象 / 外貌 + 行事调性 / 语气 + 背景」结构，
   或用户说"存个角色""从书里摘个角色" → **类型 A：OC**
2. **关于用户自身的数据？** —— 是用户自己的【偏好 / 思路 / 方法论 / 画像 / 身份锚点】，
   而不是在讨论某个外部话题。例：「我的哲学倾向是…」「我习惯 dossier 式填充」「我 git 不熟」
   → **类型 B：User（用户自身）**
   · ⚠️ **q-2 分类铁律（例外）**：即使措辞像在谈某话题（如"用户的哲学倾向"），
     只要主语是**用户本人**的元关联，就归 User 包，**不进话题类目**。
     故「哲学」类目下只放尼采这类真话题，不放"用户的哲学观"。
3. **外部资料 / 论文 / 文章 / 通用笔记？** —— 在讨论某个外部主题（尼采、数学、某篇论文…），
   或一段通用想法 / 日志：
   · **论文 / 资料 / 长文，且用户要"归档 + 理解/综述"** → **类型 C：论文 / 资料**
   · **零散文本 / 通用想法 / 短笔记（无"读懂"意图）** → **类型 D：通用笔记**

（若明显是角色但用户没明说，按类型 A 走；拿不准就问一句，但默认优先匹配上述强信号。）

## 第 1 步：按类型派发（加载对应技能）
判定后，**加载**对应技能并把它跑完：

- **类型 A → OC**：`oc-dossier`（store 分支）
  （它首行跑 `references/oc_classify.py` 拿 verdict，再分流 structured / ambiguous 两路，
   最终都按 OC 三层铁律落 基础包+故事包+拓展包。本技能不介入拆包细节。）
- **类型 B → User（用户自身数据）**：走 User 流程
  · 若为「跨项目画像 / HMA 设计偏好」这类**已结构化的稳定事实**，且来源正是 WB 的
    `~/.workbuddy/MEMORY.md` 与项目 `.workbuddy/memory/MEMORY.md` →
    直接跑 `scripts/build_user_package.py`（确定性、幂等、全量原文灌入 `User/profile`）。
  · 否则（零散的用户偏好 / 思路笔记）→ 按 `hma-ingest` 流程落 `User/<子主题>/`，
    但**牢记 q-2 铁律**：只放"用户自身"内容，不要把外部话题塞进 User。
- **类型 C → 论文 / 资料（归档 + 理解综述）**：`hma-ingest`（文章/资料分支）
  （专项流程：拆成 `<主题>-orig` 原文包 + `<主题>-review` 理解综述包，同 scope 互链；
   **必须遵循下方「嵌套逻辑关系」规则生成路径**，见第 2 步。）
- **类型 D → 零散文本 / 通用想法 / 笔记**：`hma-ingest`
  （通用收录流程；**必须遵循下方「嵌套逻辑关系」规则生成路径**，见第 2 步。）

## 第 2 步：嵌套逻辑关系（所有落库路径的通用纪律）
无论派发给哪个技能，只要是「新建文件夹 / 包路径」，都**按嵌套逻辑关系生成**，不要拍平。

- **规则**：路径应反映内容的逻辑从属，而非一次性摊平。
  · 用户给一篇「尼采综述」→ 应是 `Other/哲学/尼采/`（命名空间/主题/子题 三级），
    其下两包：`<尼采原文.md>` 与 `<尼采综述与理解.md>`（原文包 + 理解综述包）。
  · 同理 `Other/科学/数学/`、`Other/科学/物理/` …… 学科→子学科自然嵌套。
  · OC 同理：`原创角色/<角色>/`（角色下再分 core/origin/ext，已由 OC 铁律定义）。
- **检索自洽（Option A，已落地）**：引擎 `query(package_id=...)` 支持**前缀/子孙检索**——
  `query("尼采", package_id="哲学")` 会命中 `哲学/尼采` 子树；`query("尼采", package_id="哲学/尼采")`
  精确到该节点。故**嵌套不破坏检索**，放心嵌套、不必摊平。
- **何时不嵌套**：内容本身只有一个层级、或用户明确要摊平时，才用单级 `Other/<主题>/`。
- **命名语言（R59 用户拍板）**：**新建文件夹一律用中文**（如 `哲学/有限空间必然趋同`）——
  中文路径的检索/锚点/互链已全链路实测无碍，"路径必须英文"是过时惯性，不是本引擎的约束。
  **唯一开口**：用户主动要求英文、或内容处于明显英文语境（如英文论文按原名归档）时才用英文。
  顶层命名空间已统一汉化（用户/项目/原创角色/日志/其他），旧英文名（Other/User/META/OriginCharacter/daylog）已成历史；
  新建议一律中文，英文仅留上述「唯一开口」场景。

## 第 3 步：回报（含「归类开口」）
派发并落库后，简要回告用户：
- 判定了什么类型（A/B/C/D）
- 加载了哪个技能、落到了哪个命名空间 / 路径
- 建了哪些包、是否互链
- 若类型拿不准、或某段内容跨类型（如"既像论文又带个人批注"），明确指出并请用户确认。

### 归类开口（收尾钩子，非阻塞，强制）
归类本来就是难点，但**不在流程中阻塞询问**——统一在收录完成后，由 `hma-ingest` 第 6 步主动输出「收录钩子」告知落点 + 触发关键字。本技能只把纪律传下去，钩子文本由 ingest 技能输出。要点：
- 凡落点不是用户明示、而是 AI 推断的，必须给出**相似已有包（归并候选）** + **可触发关键字**（「合并 / 移包」）。
- 用户回复关键字 → 加载 **`hma-relocate`** 技能（确定性调用 `relocate_package.py`，整包搬迁 或 合并进已有包，索引确定性重挂；跨包 `linked` 按 id 不受影响）。
- 用户不回应 = 默认接受当前落点，绝不追问。开口是"告知 + 可触发"，不是"每次都要用户拍板"。

## 纪律（铁律，不得违反）
- **薄层**：本技能只判定 + 派发，**绝不**自己写 `memory/` 文件、不重造拆包/落库逻辑。
- **理解归你、落库归脚本**：分类是理解决策；实际写 `.md` / 索引由被派发的技能与引擎做。
- **q-2 铁律优先**：用户自身数据 → User 包，不污染话题类目。
- **嵌套优先**：新建路径按逻辑关系嵌套，引擎子孙检索已支撑，不必摊平。
- **内容即数据**：最终落库一律直写 `memory/`（经对应技能）。
