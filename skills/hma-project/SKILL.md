# HMA Project（项目工程收录 · README 式功能拆包）

## Overview
把"一个项目 / 模块"的工程信息收进 HMA 长期记忆。与 `hma-ingest` 的通用分支不同，本技能针对**工程对象**采用「README 式功能拆包」：站在读者（新人 / 未来的你）视角，按"要做什么 / 长啥样 / 怎么变的 / 啥规矩"组织，而非按技术子系统（引擎 / 技能 / MCP / 检索）切。

落点：`memory/项目/<项目名>/`。

## 何时用（命中即加载）
- 用户给一个项目 / 模块，要收进 HMA，且意图是"工程信息 / 结构 / 需求 / 进度"。
- 关键词 / 口语化见上方描述。
- 与 `hma-ingest` 的边界：零散文本 / 笔记 / 用户自身数据走 `hma-ingest`；**成体系的项目工程对象**走本技能。

## 拆包策略（README 式，单一真相源见 `信息架构与拆包策略`）
一个 md 装一类职责，落 `memory/项目/<项目名>/`：

- **需求清单（`需求清单.md`）**：项目要做什么，显式标 `已完成` / `未完成`（活待办 / roadmap）。这是项目的"活待办"。
- **项目结构（`项目结构.md`）**：只描述目录与文件布局。**严禁把铁律 / 约定 / 架构决策等"死东西"塞进此文件**——结构就是结构。
- **开发日志（`开发日志.md`）**：结构化、按时间顺序的工程记录（决策 / 改动 / 踩坑经过）。
- **约定 / 铁律（`约定.md`）**：把"死东西"（编码铁律、协作约定、不可违反的规则）单独成文件，与结构、日志解耦。
- 其余按需：`架构.md` / `接口.md` / `测试.md` 等，每个 md 单一职责。

> 与"按子系统切（引擎/技能/MCP/检索）"的区别：子系统切是**实现视角**，README 式拆包是**读者视角**——新人打开项目先想"要做什么（需求）、长啥样（结构）、怎么变的（日志）、啥规矩（约定）"，而非"引擎代码在哪"。

## 收录流程
1. **定位 root**：`memory/项目/<项目名>/`（`<项目名>` 用用户给的或推断的中文名）。
2. **判模块 / 比对 index**：跑 `python -m hma.engine query <root> "<项目名>"` 看是否已存在该项目包；存在则**增补**对应 md，不存在则按下方结构新建。
3. **按模块落库（每个 md 一个包）**：对每个要建的 md，用引擎直写 `memory/`：
   ```bash
   cd hma && python -m hma.cli --root memory/项目/<项目名> write \
       --id <项目名>-需求清单 --title "<项目名> 需求清单" --summary "<≤30字>" \
       --tags "project,<项目名>,需求" --body-file /tmp/<项目名>-需求清单.md
   # 项目结构 / 开发日志 / 约定 同法，id 分别为 <项目名>-项目结构 / -开发日志 / -约定
   ```
   正文用 `##` 分节（需求条目 / 目录项 / 日志条目 / 铁律条目），`##` 即 L2 锚点。
4. **互链（按需）**：需求 / 日志 / 约定之间真相关才 `link`，不编造 id。
5. **daylog 纪律**：结构化工程跟踪（需求状态、决策）进上面的项目包，**不进 daylog**；只在 daylog 写一句大事件简介 + `linked` 到项目包（闲话 + 关联，不承载真相）。
6. **记当日账（daylog）**：收录成功后给当天单日记录包追加叙事，`--linked` 指向本次建的项目包：
   ```bash
   cd hma && python -m hma.engine 日志 add "<一段叙事：这天把 <项目名> 工程信息收进了 HMA>" \
       --linked "<项目名>-需求清单,<项目名>-项目结构" --tags "project,<项目名>"
   ```
7. **回报（含归类开口）**：列出建了哪些 md / 落点；若项目名是你推断的，带固定句式：
   > **当前归类为 `<项目名>`，如有异议可以切换为 `<次优候选>`（一句话理由）。**
   用户答"换"即跑 `python scripts/relocate_package.py memory "<路径A>" "<路径B>"`。

## front-matter 规范（落库必填）
- 必填：`id`（kebab-case，建议全局唯一 `<项目名>-<短主题>`）、`title`、`summary`（≤30 字）、`tags`（2–5）、可选 `aliases` / `linked`。
- 引擎托管（**不要手填**）：`anchors`（由正文 `##` 派生）、`created` / `updated`。
- 正文以 `# 标题` 开头，`##` 即子事件锚点。

## 模块路由判定（落点决策）
配合步骤 2 的一次比对 index：
1. **判命名空间**：项目 → 落 `memory/项目/<项目名>/`。
2. **判模块**：内容语义命中哪个 README 式功能模块（需求清单 / 项目结构 / 开发日志 / 约定）。
3. **比对 index**：该模块包是否已存在？
   - **存在且同物** → **增补 / 覆盖该包**（update 同包，不新建）。
   - **存在但过大**（体积触发） → 在该模块下拆子包 / 子事件 id。
   - **不存在** → 仅当凝聚性确实成立，按「嵌套逻辑关系」新建模块包。
4. **严禁**：把不同模块内容塞进一个包；为小内容预建一堆空模块包。

## 纪律（铁律，不得违反）
- **项目结构文件不装铁律**：铁律 / 约定 / 架构决策一律进 `约定.md`，不在 `项目结构.md` 混。
- **不提前拆小东西**：小内容先作同包内不同事件 id，不必硬拆独立包；过度拆分信号（一两句包 / 高频互链成网）应合并。
- **模块是默认路由指南非强制**：命中模块则增补同包、过大则拆子包、跨模块新主题才新建；不为小内容预建空模块。
- **内容即数据**：只写 `memory/` 下的事件 `.md`，直写权威存储；索引可由 `.md` 重建。
- **嵌套逻辑关系**：项目下按子主题嵌套（如 `项目/<项目>/<子模块>/`），引擎子孙检索已支撑，放心嵌套。
