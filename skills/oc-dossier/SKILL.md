# OC Dossier（存 + 唤醒 一体技能）

本技能把「把一个角色写进 HMA 长期记忆」与「把已落库角色唤醒扮演」两件事合并到一个入口：
存侧保证包可被确定性检索，唤醒侧保证检索被确定性使用，靠同一份 `.md` 与四要素变体 dict 衔接（名字解析走 `oc_registry` 扫 person/topic 变体），不引入新状态。

## 两个入口

- **存（store）**：把角色 / OC 档案写进 `memory/原创角色/<char>/` → 见「存角色流程」。
- **唤醒（wake）**：对话里叫到已落库角色名字、让其回应 → 见「唤醒角色流程」。

## 何时用（命中即加载）

- 用户丢来一段文本 / 一个文件，意图"存一个角色 / OC 档案"。
- 口语化存触发：「把这个角色记下来」「从这本书里摘个人物」「帮我整理成 dossier」「这段设定收进记忆」。
- 用户叫到某个已落库 OC 的名字 / 别名并像对其说话：角色扮演启动、按名字唤醒、让某角色回应。
- 口语化唤醒触发：「维罗妮卡，你在干嘛」「扮演一下 XX」「XX 会怎么做」「XX 你怎么看」。
- 关键词：OC、角色档案、人物档案、dossier、存角色、摘角色、收进记忆、角色扮演、唤醒、扮演、叫名字、按名启动。

# 一、存角色流程（store）

## 首行铁律（最重要）

**不要自己判断"这算不算结构化"，先跑判定器拿确定性 verdict：**

```bash
python <skill>/references/oc_classify.py classify <用户给的源文件>
# 或只看走哪条路：
python <skill>/references/oc_classify.py route <用户给的源文件>
```

判定器是纯文本规则（无 LLM），输出 `verdict`（`structured` / `ambiguous`）+ 命中信号。以它的输出为唯一分流依据，不要覆盖。

## 两路分流

### 路 A：structured → 自动落库（无需你理解）

源已是一份结构化 dossier（硬数据卡 + 分节标题），直接确定性切片落库：

```bash
# 在能 import hma.hma_core 的目录（如仓库根）下运行
python <skill>/references/dossier_build.py --id <角色id> --source <源文件> [--name <显示名>]
```

- `<角色id>`：注册用 id（如 `veronica` / `luzhao`），由你按角色定（拼音 / 英文名）。
- 脚本按三层铁律切片：数据卡 + 形象 + 行事调性 → 基础包；背景故事 → origin 包（默认必有，哪怕一句短语也独立成包）；能力 / 事件 / 关系合并拓展包。
- 落库后**必须**刷新唤醒快照（见下方「共同后置」）。

### 路 B：ambiguous → 你来理解抽取（AI 路）

源是散文 / 书摘 / 零散设定 / 只有对话，判定器返回 `ambiguous`：

1. 你亲自读散文、按下方「三层拆包铁律」抽取字段，写：
   - `<id>-base`（硬数据卡 + 形象 + 行事调性）
   - `<id>-origin`（背景故事包，默认必有；哪怕只有一行字 / 一句短语也独立成包；仅当该 OC 确实无任何背景故事时省略）
   - `<id>-ext`（关系 / 信条 / 能力，合并 1 个）
2. 落库：直接 `Memory(root).write(...)` + `link`（`memory/原创角色/<id>/` 为单一权威存储，直写即可）；包结构即三铁律范式，不经任何 `build` 步骤。
   - front-matter 字段严格按 AIMH 设计规范（`memory/项目/AIMH-design-journal/SCHEMA.md`）：无 `id`/`aliases`/`features` 字段、四要素 person/topic/location 用 list 包裹 `[{规范名:[变体]}]`（读取侧兼容旧式裸 dict）、`event_date` 字符串、`pkage_created`/`pkage_updated` 时间戳、`anchors` 唯一形态 `{Chapter, about, keywords}`（无 `locator`/`tags`）。
3. 落库后**必须**刷新唤醒快照（见下方「共同后置」）。

> 详细拆包方法、Memory API 签名、内容模板与范例见 `references/method.md`（虚构角色苏野 / 小满演示，不含真实用户 OC）。

## 三层拆包铁律（两路都守）

1. **基础包（必有，仅 1 个）** = 姓名 + 形象 + 语气 / 调性。这是「AI 能基本扮演」的最小可运行单元。无论 OC 多浅多深，这一层永远只有 1 个包（`{id}-base`）。
2. **origin 包（背景故事包，默认必有）** = 人物背景故事，**无论长短独立成包**（`{id}-origin`）。哪怕只有一行字 / 一句短语也单独拆出；**只有确实没有任何背景故事的 OC 才省略 origin 包**——不再有「短就并进基础包」的模糊判定。内部用锚点索引实现细粒度召回，不切碎文件。
3. **拓展包（有则分）** = 感情 / 与其他角色关系 / 战衣 / 武器 / 能力 / 信条……只在存在时才分立（`{id}-ext`）。极简 OC 可以一个拓展包都没有。

该铁律须兼容两端：无背景故事的极简 OC（仅基础包）与有背景故事的 OC（基础 + origin 包[可仅一句短语] + 可选拓展包）。

## 拆包步骤

1. 识别 OC 的最小基础信息：姓名、形象描述、语气 / 说话调性 → 合并写入 **1 个基础包**。
2. 抽取背景故事：背景故事**独立成 origin 包**（`{id}-origin`），无论长短；哪怕只有一行字 / 一句短语也单独拆出，仅当该 OC 确实无任何背景故事时省略 origin 包。对正文（尤其较长叙事）中每个有意义的段落 / 章节在索引层注册**锚点**（见 `references/method.md` 的 HMA anchors 用法）。
3. 扫描拓展维度：感情、关系、装备、能力等——凡原文有独立成段的内容，按维度分立为拓展包；无则不分。
4. 落库后验证：包数符合预期、无重复 id、锚点可经 `query_anchors` 精准命中、`read_section` 能读回对应段落、`rebuild()` 后锚点不丢。

## 不可违反的规则

- **背景故事原样收录，禁止综述化 / 压缩**：起源史诗、人生经历等背景文本，按原文长度完整写入 origin 包（背景故事包）正文；AI 不得重写、精简、或自造小标题。需要细粒度召回时，用索引层锚点，而非切碎文件。
- **不动用户 OC 源文件**：抽取走读副本或构建脚本从权威源抽取；草稿残留、笔误等由用户手动清理，AI 不擅自修改源文件。
- **一个角色一个基础包**：不得把姓名 / 形象 / 语气拆成多个包（已踩过的反例）。

## 共同后置（两路都要）

落库即生效——`oc_registry.py` 的 `discover()` **实时扫 `memory/原创角色/`**，无需快照 / 缓存命令。落库后直接验证新角色能被名字解析到：

```bash
# 在仓库根目录下运行（无需 index / 快照）
python scripts/core/oc_registry.py find "维罗妮卡你在干嘛"   # 应解析到 veronica-base
python scripts/core/oc_registry.py list                      # 列出所有已登记 OC
```

> 早期文档中的 `python scripts/core/oc_registry.py index` 已废弃：解析器为无状态实时扫描，没有 `index` 子命令，也不需要刷新快照。

# 二、唤醒角色流程（wake）

## 调用流程（铁律四步）

1. **检测 + 解析（确定性）**：用 `scripts/core/oc_registry.py find "<用户原话>"` 把出现的名字 / 别名解析到具体 OC 的 `base_id` 与 `root`（实时扫 `memory/`，无需快照）。若未命中任何已登记 OC，则不进入扮演，按正常助手响应。
2. **启动基础包（扮演最小单元）**：`Memory(root).read_body(base_id)`（或 `read` 后取 `.body`），载入「姓名 + 形象 + 语气 / 行事调性」。这是 AI 能基本扮演的全部所需。
3. **进入角色回应**：以该 OC 的语气 / 行事调性回答用户本句话。基础包已含形象与口吻，无需先读故事 / 拓展。
4. **惰性召回（按需）**：仅当用户问到具体内容时，才从其他包取细节：
   - 问「过去 / 起源 / 经历」→ 在 origin 包（背景故事包）上 `query_anchors(q)` 取摘要，必要时 `read_section(origin_id, heading)` 读整段；
   - 问「能力 / 战衣 / 关系 / 信条 / 拓展设定」→ `read_section(ext_id, "对应小节标题")`；
   - 不相关问题不强行塞角色背景，保持对话自然。

> 完整触发词清单、惰性召回 API 用法、身份边界与唤醒范例见 `references/flow.md`（虚构角色演示，不含真实用户 OC）。

## 身份边界（不可违反）

- **扮演时你 = 该 OC，不是助手**：用第一人称、该角色的语气与视角回应；不要暴露「我是 AI / 我是助手」。
- **退出信号（交还控制权）**：当用户说自己的真名 / 「退出角色」/「你是 AI 吗」/「回到助手」/ 明显改回对助手说话时，立即停止扮演，恢复普通助手身份响应。
- **连续扮演**：一旦进入角色，后续回合保持该 OC 身份，直到出现退出信号；不要每句都重新「加载」。
- **隐私 / 拓展边界**：角色「私人 / 情感」类拓展设定是用户为特定互动对象设计的扩展，只在该类亲密语境下自然流露，不主动对外广播；不把 OC 的私密设定泄露给无关提问。

## 不可违反的规则

- **先做名字解析，再扮演**：禁止在没解析到具体 OC 基础包的情况下凭记忆硬演。
- **基础包是唯一扮演入口**：永远从 `base_id` 启动；故事 / 拓展包只做惰性补充，不得跳过基础包直接演深度设定。
- **不改写用户 OC 源 / 记忆包**：唤醒只读不写；若发现包内容需修正，提示用户，交由本技能的「存角色流程」处理。
- **范例不写真实 OC**：本技能及 `references/` 所有范例均为自创虚构角色，不含任何真实用户 OC 内容。

# 三、纪律（两路通用）

- **隐私**：范例与测试一律用自创虚构角色，禁止把真实用户 OC 内容写进技能或落库脚本。
- **确定性归脚本、理解归 AI**：判定（oc_classify.py）与自动切片（dossier_build.py）交给脚本；只有 ambiguous 才由你理解。
- 路 A 与路 B 出口一致——都落「基础包 + origin 包（背景故事包，默认必有；仅无背景故事者省略）+ 拓展包（有则分）」，唤醒层无差别解析。
- 唤醒只读不写；任何修正需求回流到「存角色流程」（原样收录、不动源文件、保留 anchors）。
